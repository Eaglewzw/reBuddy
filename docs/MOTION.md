# 当前动作事件与历史控制接口

当前 `main/main.c` 使用 `rb_pet_t`，不实例化旧轨迹引擎或 `rb_arm_t`。`rb_pet_set_sink()` 接收 `rb_pet_event_t`：action_id、request_id、source、target_state、lazy风格和单调timestamp_ms。默认sink仅写日志，两路CAN保持待机；不根据每张图片生成电机命令。

当前行为参数来自 `config/behavior_defaults.json`，屏幕资源由 `tools/build_pet_assets.py` 生成，稳定姿态/切换规则见 [REFERENCE_IMPLEMENTATION.md](REFERENCE_IMPLEMENTATION.md)。STOP直接冻结屏幕并清空请求，不自动发回位命令。

下文为**历史关节轨迹草案和未来接入说明**。其中 `actions.json`、`rb_life.c`、旧风格系数及ENTER触发路径均不用于当前应用，保留旧测试以防回归。真实控制接入需要另行完成，不属于本阶段屏幕交付。

# 动作数据与机械臂接入

六个动作对应方案书中的探头、蹭蹭、害羞、小舞蹈、歪头和打瞌睡。`config/actions.json` 为唯一数据源，生成的 `rb_actions.c` 放入 Flash。配置明确标记 `hardware_validated: false`。

每帧包含相对标定中性姿态的七关节电机角度偏移、到达时间和表情。单位是电机角度，不是末端位移或夹爪开口毫米数。现有正负号与关节组合只是预览草案，**不能证明末端实际会前伸、缩回或避碰**，必须结合真实安装、夹爪传动、载荷与姿态重新标定。最后一帧回到中性偏移零。

打瞌睡的末帧也回到中性姿态；最终实体休息姿态尚未定义。未来若引入非零睡姿，必须同时更新生成器规则、唤醒过渡与测试。

屏幕交互现由 `rb_life.c` 与 `rb_gesture.c` 持续更新目光、舒适度和神态，不再把每次触摸映射为整段关键帧动作。以下规则适用于保留的关键帧引擎（休息/唤醒、实体 ENTER 和显式动作调用）；屏幕生命感不修改七轴目标。

## 调度规则

动作使用五次平滑插值。每次切换先计算当前姿态，再以该姿态为新动作起点；不直接跳到下一个动作的第一帧。连续交互采用最新事件替换当前动作，不积压动作队列。动作结束需要最后一帧已到时间且指令已回位。

活泼为原始时长与幅度；慵懒的幅度为 0.55、时长为 1.65 倍、速度上限为 0.55 倍。风格参数在动作开始时快照，切换按钮不会在动作中途突然改变幅度。当前速度硬上限默认 5°/s、相对偏移上限 8°。

插值实现保证指令位置连续并限制指令速度；不保证跨动作打断时加速度或加加速度连续，也不等同于真机轨迹规划器。真实驱动仍需实现加速度约束、控制周期监控、反馈跟随和工作空间保护。

## 当前真实控制边界

`main/main.c` 的 `rb_arm_t` 没有连接驱动；CAN 收发器保持待机，控制器未启动。屏幕动画和关节指令预览可运行，实际电机不会跟随。这是第一周屏幕 Demo，不能作为六个实体动作已经完成的验收结果。

当前仓库只提供机械臂适配接口，尚未实现 RS 电机协议、反馈订阅或实时运动任务。后续控制适配应基于可公开使用的协议与实现，保持项目可独立构建。J7 夹爪需要单独标定，不能把全开端点直接用于桌宠的小幅开合动作。

## 接入接口

`rb_arm.h` 定义 `feedback / send / stop` 和标定数据。`rb_arm_enable()` 只验证、挂接会话，不替代电机底层使能事务；调用前由硬件驱动完成全部就绪检查。

接入步骤：

1. 实现独立的 RS 协议驱动和运动任务，处理双 CAN 选择、七轴新鲜反馈、故障、限温/电流、已确认标定和总线独占。
2. 标定中性姿态、各关节绝对上下限和当前姿态；启动姿态须在中性姿态 ±0.5° 内。校准记录未经确认时拒绝动作。
3. `feedback()` 非阻塞地返回七轴真实角度和最后采样时间；禁止用指令值冒充实测值。
4. `send()` 只替换最新目标，不排队；返回值仅表示接受目标。真实到位必须由反馈判断，并将到位结果接入行为时间轴，才能完成实体表情同步与回位验收。
5. `stop()` 取消未执行目标并请求控制器安全保持；软件停止不等于失能或切断电源。断线与急停后的保持/失能策略应依据真实机构确认。
6. 在动作启动界面增加明确的实机启用流程，显示已标定状态，绑定当前反馈；GPIO 急停由运动任务独立监视。不要让电机安全依赖 LVGL 锁或 UI 刷新。

接口包装层在反馈超过 100ms、发送失败、非有限值、绝对限位、上次目标跟随偏差超过 3°、目标增量超速、更新超过 100ms 或外部急停时锁存停止并调用驱动停止一次。这是应用层检查，底层需保留自身保护。复位只清除桌宠软件状态，停止后的机械臂会话不会自动重新启用。

## 协作臂扩展

将来可实现同一应用接口，但必须由协作臂控制器承担实时插补和停止。优先传递经过审核的动作标识或完整轨迹，依据其协议返回执行状态。现阶段没有实现协作臂通信适配。
