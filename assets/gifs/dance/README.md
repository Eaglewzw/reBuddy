开场 ID 43 为 5.5 秒，收尾 ID 44 为 7 秒，均不占作品的手动步骤。GIF 时间以 10 ms 为单位，和真实轨迹的舍入误差不超过 5 ms。夹爪随当前轨迹变化，02/06 包含开合。

08 使用 16 张完整角色原画逐格转身，不做光流、交叉叠图或局部拼接，排除 56°/59°/62° 偏侧面姿态，保留两个来回；09 正对 8 字轨迹平面，显示淡色完整路径、随动作描绘的亮线及末端光点。轨迹线在首尾淡出，不影响统一待机衔接。这些是屏幕动画的视觉调整，PC 实机轨迹不变。

板端共享调色板为轨迹线预留三个蓝青色，避免细线在颜色压缩时变成灰色；总色数仍为 32，不增加帧率或分辨率。

`manifest.json` 保存 GIF 哈希、轨迹哈希、RGBA 帧哈希及逐帧时长。`rgba/` 是固件生成的透明素材输入，必须随 GIF 一起保留。透明连杆空隙显示原小屋墙面，白色眼睛与金属高光保持不透明；不通过全局删除白色来抠图。

运行资源保留 160×160 原生索引平面，以预乘透明度双线性重建为 240×240，居中显示在 320×240 房间中，使用共享 32 色、8 级覆盖率和有限深度差分。保留原采样时序（名义 12.5 FPS），最长片段允许 256 帧，不强制扩展为 20 FPS。各动作首尾由渲染器输出一致的互动姿态，不在打包时硬换首尾帧。08 使用已确认的完整角色逐格原画，自身循环首尾一致；其待机画面与其余动作不完全相同，因此跨动作切换仍有画风差异。

安装当前确认版时，从 `build/dance-original` 取基础动作，08 取 `build/dance-3d/whole_turn`，09 取 `build/dance-3d/multiview`。正式 GIF 和透明帧已经保存在本目录，不依赖 build 目录即可重建固件资源。重新渲染并审核后，再运行 `python3 tools/install_dance_cartoon.py --reviewed`、`python3 tools/build_screen_preview.py` 和 `python3 tools/build_room_font.py`，随后构建并运行主机测试。只替换 GIF 不会更新固件资源。

新动作使用 ID 45–54；原 ID 33–42 永久退役。含旧动作的已保存作品会明确显示“旧版作品”，保留原记录，只有用户确认重建并保存才替换，不能按相同编号静默播放新动作。详见 [编舞](../../docs/CHOREOGRAPHY.md) 与 [预算](../../docs/DANCE_OPTIMIZATION.md)。
