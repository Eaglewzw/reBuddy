# 固件动画资源

当前资源版本为 `gif-v2-rgb565`，由 [10 个日常 GIF](../gifs/daily/README.md) 和 [10 个舞蹈及开场收尾 GIF](../gifs/dance/README.md) 生成。

- `frames.bin`：完整 320×240 GIF 帧转换为 RGB565 后去重；每个动作保存独立基准帧，其他帧优先保存经 zlib 压缩的像素差异。表情、问号、Z 与小屋背景均来自 GIF。
- `room.bin`：320×240 RGB565 小屋背景，用于基础界面与回退显示。
- `manifest.json`：源 GIF 校验值、去重帧及压缩大小、手爪触摸区域、动作映射与原始帧时序。

运行时由 `main/pet_animation_table.c` 的时间轴选择图片。两块显示帧缓存加一块基准帧缓存，共占 460,800 字节 PSRAM，比整帧压缩多用 153,600 字节。差异帧只依赖独立基准帧，不串联依赖，支持跳帧、倒放与暂停恢复。存储压缩本身无损：解码与转换后的 RGB565 帧逐像素一致。日常不减色；板端舞蹈经用户确认使用共享 256 色色板，原始 GIF 完整保留。日常保留 GIF 的 120/130 ms 帧时间，平均 8 FPS；舞蹈整帧固定适配至 240×240 后居中，高帧率源按 100 ms 取帧，底盘回转保留 150 ms 原帧时序，基本动作每段 2400 ms，开场／收尾各 3000 ms；硬件实际刷新率需实机验证。资源失效时回退到待机或占位显示。

使用 `python3 tools/build_screen_preview.py` 从当前日常与舞蹈 GIF 重新生成资源和 C 帧表，再编译固件。原画变化时先运行 `python3 tools/export_gifs_v2.py`。

连杆空隙的墙面颜色已在 GIF 导出时通过 [逐姿态种子配置](../config/preview_cavity_seeds.json) 修复；固件转换保留这些像素，不另外重新抠图。

舞蹈在显示层通过 `rb_assets_dance_frame` 合成现有 `room.bin`，原始帧缓存与独立解码基准保持不变。只处理边界相连的浅色背景，保留内部高光；不增加带背景的 Flash 帧副本。首次舞蹈预览分配 153,600 字节合成缓存和 307,200 字节遍历队列（ESP32 上位于 PSRAM），连同原解码缓存合计 921,600 字节，关闭资源时释放。

舞蹈轮廓合成对紧邻外部背景的一像素浅色边缘去除原浅底贡献，再按覆盖率混入小屋颜色，减少白色毛边。处理仅限轮廓边界，保留内部高光、眼睛与实色轮廓；不修改原 GIF、不改变动作比例、不新增动画缓存。

存储编码按每帧大小选择：原始 RGB565（回退帧）、zlib 整帧、单层 XOR 差分或 RGB565 色表＋zlib 索引。色表编码在已有帧缓存内倒序展开，无额外帧缓存；差分基准允许为独立色表帧，仍禁止依赖链。
