# reBuddy 交互动作与编舞产品需求说明

用途：交给本地 Codex 进行需求拆分、界面开发、动作调度和机械臂适配。本文汇总用户已确认的产品方向及认可的动作库，并补充可实现、可验收的开发约定。本文不代表实体动作已经实现或实机验证通过。

## 1 产品目标与已确认需求

reBuddy 是基于 ESP32-C5 和 reBot RS 的机械臂桌宠。屏幕中的角色提供表情和身体动画，现实机械臂通过动作回应用户，形成可触摸、可陪伴、可创作表演的桌面体验。

| 已确认事项 | 产品要求 |
| --- | --- |
| 屏幕位置 | 固定在桌面或机械臂底座，不随末端运动 |
| 主画面定位 | 保留当前小屋和角色的生活感，通过直接触摸互动，不铺满情绪按钮 |
| 日常互动 | 复用现有触摸规则，补齐对应实体动作，动画与机械臂同步表达 |
| 自主小动作 | 支持偶发的小动作，屏幕与实体配合；用户互动优先 |
| 编舞入口 | 独立页面，用户排列动作、调整节奏并保存舞蹈 |
| 动作丰富度 | 以现有动作扩充，采用已认可的 12 类动作及停留积木 |
| 展示目标 | 既能直接体验，也能编辑自己的表演，适合创客展示与视频演示 |

同步指情绪、运动方向、关键姿态和阶段时间一致，不要求机械臂逐关节复制卡通角色。眨眼、问号、Z 等纯视觉效果无需强制对应实体运动。

本文中的每段最多 8 步、保存 3 段、节奏档位、重复次数和停留范围属于建议开发默认值，集中配置，可在体验后调整；不把这些数值表述为用户已逐项确认。

范围不包括音乐识别、自动跟音乐节拍、任意角度自由示教、神经网络训练及新增传感器。旧文档中这些方向不得自动纳入本次交付。

## 3 日常互动和自主行为

| 触发 | 屏幕表现 | 拟配套的实体动作 |
| --- | --- | --- |
| 轻点角色 | 抬头看你 | 小幅抬起末端，注视停留后回位 |
| 缓慢抚摸身体 | 轻蹭、笑眼 | 末端小幅侧倾与往返轻摆 |
| 快速划动 | 疑惑歪头 | 腕部小幅倾转后回正 |
| 1.2 秒内轻点三次 | 害羞缩回 | 肩肘收拢，保持收拢姿态 |
| 收拢后温柔抚摸 | 安抚展开 | 从收拢姿态慢慢舒展 |
| 有效抚摸手爪累计约 0.6 秒 | 开心回应 | 抬起、舒展，空载夹爪轻开合 |
| 无操作 60 秒或设置中休息 | 慢慢入睡 | 进入标定后的休息姿态 |
| 睡眠时长按左下角 | 迷糊唤醒 | 从休息姿态返回互动姿态 |

沿用现有手势阈值、手爪动态区域、开心冷却和优先级语义。静止长按、摸头不累计摸爪开心；睡眠中普通触摸不直接唤醒。详细值以 assets/config/behavior_defaults.json 和 rb_pet.c 为准，不重新套用早期方案中的三秒开心阈值。

触摸确认后及时提供屏幕反馈；实体动作经过调度准备再启动。动作执行中不无限排队。保留最多一个仍有效的待执行请求；新的同类触摸不反复重启动作。动作退出和抢占采用允许的过渡，不把屏幕已有的倒放方式直接套给实体轨迹。

自主小动作新增两类：偶尔小幅左右张望，以及轻微调整身体姿态。优先复用点头、摇头或摇摆的低幅度标定变体，不额外增加大量动作类别。

自主动作仅在正常待机、没有触摸、没有设置或编舞页面、没有播放或故障时触发。建议每次回到正常待机后采用 20～40 秒随机等待；用户互动取消待触发任务。自主动作不重置用户无操作计时，避免自己活动导致永远不入睡。

已有动作播放和入睡过渡期间不插入自主动作。熟睡时机械臂保持已验证的休息姿态，呼吸和 Z 在屏幕循环；不默认通过持续实体微动模拟呼吸。

## 4 动作库与表演内容

目标动作库共 12 类，另含停留积木。下列英文 ID 是建议稳定标识，现有六类保留与仓库枚举的映射，不以改名方式破坏现有行为。

| ID 与动作 | 动作意图 | 资源与用途 |
| --- | --- | --- |
| PROBE 抬头看你 | 抬起、短暂停留、回位 | 复用现有动画；互动与开场 |
| NUZZLE 亲昵轻蹭 | 轻靠、小幅往返、回中 | 复用；柔和互动段落 |
| TILT 疑惑歪头 | 侧倾、观察、回正 | 复用；俏皮停顿 |
| WITHDRAW 害羞收拢 | 肩肘收拢，停在收拢姿态 | 复用；收势与蓄势 |
| RECOVER 安抚展开 | 从收拢姿态展开到待机 | 复用；与收拢配合 |
| HAPPY 开心回应 | 起身舒展、夹爪轻开合、回位 | 复用；情绪高潮 |
| NOD 点头回应 | 末端轻俯仰，单次或两次 | 新增；配合眨眼或认真眼神 |
| SHAKE 俏皮摇头 | 末端小幅左右转向、回正 | 新增；配合淘气表情 |
| SWAY 左右摇摆 | 肩肘配合，末端沿短弧线摆动 | 新增；配合笑眼与节奏 |
| BOW 礼貌鞠躬 | 前倾、降低、停留、起身 | 新增；闭眼致意，适合收尾 |
| CLAW_BEAT 夹爪打拍 | 身体基本稳定，夹爪轻开合 | 新增；眨眼或笑眼配合节拍 |
| POSE 得意亮相 | 舒展到特征姿态、停留、眨眼 | 新增；结束后按定义回中 |

WAIT 停留积木保持当前姿态，允许低干扰的面部动画；停止改变关节目标不等于切断电机力矩。允许的停留姿态必须经实机验证。

新增动作的动画、轨迹和标定均尚未完成。已有动画只表示可以复用视觉资源，不代表对应实体动作已验证可执行。不得从 GIF 像素或卡通关节角度直接推导真实机械臂指令。

建议提供三个可编辑示例：初次见面为抬头、歪头、点头、鞠躬；害羞撒娇为收拢、停留、展开、轻蹭；开心营业为点头两次、左右摇摆、夹爪打拍、得意亮相。示例与用户作品采用同一种序列格式。

入睡、熟睡和唤醒保留在日常行为系统，暂不作为任意排列的编舞卡片。收拢与展开可以进入编舞，但必须具备入口姿态检查和可执行过渡。

## 5 动画与机械臂同步规则

每个动作同时定义屏幕片段、实体轨迹、入口与出口姿态、阶段时间，以及可播放的节奏范围。同步至少覆盖准备、运动、停留、恢复四个阶段；夹爪开合等显著事件使用共同阶段标记。

执行顺序为：接收动作请求，检查模式和姿态，准备所需资源与实体轨迹，确认可以执行，再通过共同的时间基准启动双方。机械臂使用连续轨迹控制，不按动画 8 FPS 跳发离散目标。同步目标是感知和阶段一致，不承诺尚未测量的零延迟。

编舞播放前先计算完整序列及连接段。上一动作出口与下一动作入口一致时直接衔接；不一致时插入已验证的过渡，并计入预览总时长。没有可用过渡就阻止同步播放、指出具体步骤，不临时猜测轨迹，也不突然回中。

以实际运动约束决定可用速度，再统一调整动画时间轴。慢／标准／快不能只修改 GIF 速度。用户选择超出当前动作标定范围的节奏时，应提示限制，不能暗中让机械臂更慢而屏幕继续快播。普通用户不直接编辑关节角度或运动幅度。

调度模式至少区分日常互动、编舞编辑、屏幕预览、同步表演、停止或故障。打开编舞页后退出日常动作调度；若有动作在执行，先受控停止并保持，不因进入页面自动回中。需要改变入口姿态时，仅在用户选择同步表演后执行已验证的过渡。编辑和屏幕预览不启动运动。

同步表演独占动作执行，暂停自主动作和日常手势动作。停止与故障处理优先级最高。日常模式下保留现有动作优先级，自主动作最低。退出编舞后清空旧请求，完成必要恢复，再重新启用日常交互。

用户停止时先取消后续步骤，向实体后端请求受控停止；屏幕显示正在停止并保持与实际停止进程相符。收到停止完成后保持姿态，不自动回零或自动重播。通信丢失、状态异常或轨迹失败时终止同步表演、显示可理解的原因；不得继续播放成功动画掩盖故障。软件停止不等同于硬件急停，接入实物前必须验证实际停止链路。

当前纯屏幕暂停功能继续保留。恢复动作必须从已知、允许的姿态开始；重启、故障恢复和重新连接都不得自动重放未完成的舞蹈。

## 6 独立编舞页面与用户流程

主画面保持小屋、角色、暂停和设置。建议在设置面板新增编舞入口，不增加情绪按钮阵列。屏幕固定安装，用户在整个实体表演过程中都能看到并触及停止入口。

编舞页采用纵向动作卡片列表，适配 320×240。建议顶部放返回、作品名和保存；中间显示可滚动步骤列表及选中项；底部放添加、节奏和播放入口。单项编辑使用弹层或子页，避免把所有操作同时塞进小屏幕。

| 操作 | 行为要求 |
| --- | --- |
| 添加动作 | 动作库分为互动、情绪、表演三组；新动作插在选中项之后，无选中项则追加 |
| 修改顺序 | 选中卡片后前移或后移；首尾越界操作禁用；拖拽排序不作为交付前提 |
| 删除 | 删除选中步骤，更新序号与预估时长；不影响其他作品 |
| 调整节奏 | 整段慢／标准／快三档；仅提供全序列均可执行的档位 |
| 重复与停留 | 支持该动作声明的重复次数，以及动作结束后的停留；不适用项禁用 |
| 屏幕预览 | 展示动作、顺序及过渡效果，机械臂保持静止 |
| 同步表演 | 连接、标定和姿态检查通过后执行，显示当前步骤并提供明显停止入口 |
| 保存与加载 | 保存顺序、参数和名称，断电保留；加载后不自动播放 |
| 返回 | 有未保存修改时，提供保存、放弃修改、继续编辑 |

用户流程：从主画面进入编舞，创建或打开作品，添加和排列卡片，修改参数，屏幕预览，保存，再选择同步表演。首次启动同步表演需要明确的用户操作；不能因为进入页面、选择卡片或打开作品就让机械臂运动。

建议默认每段最多 8 步、保存 3 段用户作品。WAIT 也占一步；重复在步骤内设置。建议 NOD、SHAKE、SWAY、CLAW_BEAT 支持 1～3 次，其余先固定 1 次；步骤后停留建议 0～3 秒，WAIT 建议 0.5～3 秒。所有范围集中配置。

新增作品默认自动命名为舞蹈 1、舞蹈 2 等，暂不依赖中文输入法。空序列不能播放；容量满时选择现有槽位并明确确认替换。编辑器显示基础时长与过渡后的总时长；未经标定的作品标为估算，不显示为已确认实机时长。

## 7 数据约定与代码接入

以下为建议实现契约，不是现有 API。编码时复用现有 rb_pet 行为核心、资源加载和 LVGL 页面能力，避免另写一套互相抢占的动作系统。

| 对象 | 最少需要保存或提供的信息 |
| --- | --- |
| 动作定义 | 稳定 action_id、名称、分组、动画映射、入口和出口姿态、阶段标记、重复规则、允许节奏、标定状态 |
| 舞蹈作品 | schema_version、作品 ID、名称、整体节奏、步骤列表 |
| 单个步骤 | action_id、repeat、hold_ms；WAIT 另存 duration_ms |
| 实体后端 | 连接与就绪状态、动作准备和执行、停止、执行进度、完成或故障回报 |
| 运行状态 | 当前模式、当前步骤和阶段、停止状态、错误原因；不作为自动续播依据 |

保留已有 PROBE、NUZZLE、TILT、WITHDRAW、RECOVER、HAPPY 标识映射；新增六类不打乱旧资源索引。WAIT 是序列控制项，不必增加宠物表情枚举。动作幅度、关节约束和标定数据属于动作配置，不保存在普通用户舞蹈参数中。

序列持久化可使用 NVS 或已有配置存储。保存只由用户操作触发，不在每次拖动或预览时写 Flash。需要版本字段、边界校验和可恢复写入，写入失败保留上一次有效作品。读取遇到未知动作、损坏数据或不兼容版本时提示并禁止播放，不能静默替换为另一个动作。

推荐接入位置：components/rebuddy_core/ 维护行为与模式协调；main/pet_ui.c 接入页面；新增独立的编舞序列模块和实体后端适配模块；main/main.c 将 Mock 接口扩展为可切换后端。具体文件组织由本地代码结构决定，名称不作强制要求。

继续复用 assets/gifs/daily/、assets/animation/ 和现有资源生成工具。新增六类动作需要新增或明确复用对应动画；缺失素材时可保留禁用卡片或标注占位预览，不能把旧 GIF 改名后当作新动作完成。优先不重新生成已有角色与小屋素材。

实体控制协议、关节编号与方向、单位、零位、反馈频率、速度与加速度限制、工作空间及停止语义需从实际机械臂控制工程确认。缺少这些信息时先完成 Mock、界面、存储和调度；同步播放保持不可用，不猜测 CAN 报文或使用插画像素生成轨迹。

## 8 验收与本地 Codex 执行要求

| 验收项 | 通过标准 |
| --- | --- |
| 现有交互回归 | 轻点、抚摸、快划、三连点、摸爪、睡眠和唤醒行为保持有效；无重复排队 |
| 页面分离 | 主画面保留生活感；编辑页独立；设置与编舞触摸不穿透触发角色动作 |
| 动作库 | 12 类动作与 WAIT 可识别；新增动作有真实对应资源和定义，未标定项清楚标识 |
| 顺序与参数 | 添加、删除、前后移动、重复和停留符合规则，越界输入被拒绝 |
| 保存 | 三段建议容量可管理；重启内容正确；保存失败或断电不破坏既有有效作品 |
| 预览隔离 | 屏幕预览期间不发送运动指令，Mock 可验证此行为 |
| 同步与节奏 | 实机验证关键姿态及夹爪事件对应；三个可用档位不出现持续累积漂移 |
| 动作衔接 | 收拢接展开、展开接摇摆等连接平顺；缺失过渡能够明确阻止执行 |
| 停止与异常 | 任意步骤可请求停止；故障不续播；重新连接、重启、加载作品均不自动运动 |
| 自主行为 | 仅正常空闲触发；不干扰触摸和编舞；不延后原有入睡逻辑 |
| 实机稳定性 | 连续交互和编舞运行至少 30 分钟，记录触摸、显示、内存与控制异常 |

同步验收采用能同时拍到屏幕和实物的视频，并结合动作阶段日志检查开始、峰值、夹爪和结束时刻。具体允许误差待控制反馈链路确认后设为验收参数；在该数值确定并实测前，不标记同步验收完成。主机测试只证明对应软件行为，不能代替运动性能和安全性验证。

建议开发顺序：先梳理现有资源与回归测试，再实现独立编舞页、作品存储和 Mock 序列播放；随后完成共同时间轴、过渡检查与停止逻辑；接入并标定已有六类实体动作，再补齐六类表演动作和自主行为，最终完成实机验收。此顺序不构成工时承诺。
