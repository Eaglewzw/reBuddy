# 当前显示策略与测量口径

当前版本将完整 320×240 GIF 解码为不透明 RGB565 帧，去重后保存独立基准帧与 zlib 压缩的像素差异。两块显示帧缓存加一块基准缓存，共占 460,800 字节 PSRAM。差异解码不改变画面像素，没有连续帧依赖；切换动作时载入基准，同动作后续帧复用基准。表情、问号和 Z 已绘入帧内。播放保留 GIF 的 120/130 ms 交替帧长，平均 8 FPS；UI 每 20 ms 检查时间轴，按当前时间选帧，迟到不积压补画。相同姿态停留时不重复换图，因此实际换图次数可以低于每秒 8 次。

新版画面包含房间与效果，换图可能引起整屏传输，相比旧版 160×160 角色帧增加解压和显示负载，需上板核对播放节奏。

保持SPI40MHz、两块320×40 RGB565内部DMA缓冲（总51,200字节）、显示与编舞10ms检查时间轴，输入和日常行为保持20ms。调度周期不代表实测FPS。SPI单线40MHz理论5MB/s，320×240整屏约30.7ms，未含命令、绘制及调度开销。

不变文字/样式不重复设置；身体帧编号不变不换图。主机UI测试检查相同状态更新100次发送像素为零，以及反复操作无持续堆增长。

## 串口统计

- `rb_animation body_changes`：每秒更换身体图片次数，不等于面板完整显示帧率。
- `feedback_to_ui`：原始按下到模型确认且UI处理的耗时，不含触摸芯片之前的采样或面板最后传输延迟。
- `rb_display redraw`：渲染并提交次数；静止时低是正常现象。
- `render_submit`：绘制到最后一块提交的平均耗时，包含中间等待，不含末块DMA全部完成时间。
- `pixels/redraw` / `queued`：像素量与RGB565提交速率，不含命令。
- `rb_memory`：每30秒内部/PSRAM空闲、历史最低、最大连续块；启动打印PSRAM实际大小。

当前未采集本版实机日志，不能将平均 8 FPS 的资源时间轴视为实测面板帧率或触摸延迟指标。上板应先确认色条、坐标和PSRAM，然后覆盖持续抚摸、动作衔接、睡醒与停止，记录日志及可见反馈视频。40MHz如不稳定可在menuconfig降低频率。

## 舞蹈优化版

舞蹈遮罩与边缘覆盖率改为离线计算，板端解压后直接合成。缓存峰值 600 KiB，替代原先的 900 KiB；静态侧墙不随舞蹈帧重绘，可见动画窗口为 240×192。新增 `rb_decode` 累计平均／最大解码合成耗时和失败次数。多数基础动作标准目标 20 FPS，但底盘回转姿态稀疏，慢速素材更新率也较低。须结合实机 `rb_display` 与视频检查；详见 [DANCE_OPTIMIZATION.md](DANCE_OPTIMIZATION.md)。
