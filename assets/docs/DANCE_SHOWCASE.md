# 舞台动作试播

当前默认库为 `record/dance_showcase/v10/`。21 的 P 下移 12 cm，左右 ±20°、上下 ±18° 各一次；准备朝向下倾 10°，默认正常速度一轮约 16.74 秒。v10 在左右回收途中接入上下摆动，中间连续转向；幅度、倍率和总时长均与 v9 相同。其他 11 组动作保持原数据。旧版本可用 `--bundle` 选择。

当前 21 的说明见[定点左右上下](DANCE_FIXED_TCP.md)；之前的长版扫描实验见[虚拟支点说明](DANCE_VIRTUAL_PIVOT.md)。

## 启动

已安装可承重的防坠支撑、留出动作空间后运行：

```bash
cd /home/verser/esp32/reBuddy/tools
./dance --showcase --supported
```

输入一个动作编号，等待播放完成，再选择下一个。也可以直接从一组开始：

```bash
./dance 12 --showcase --supported
```

只看菜单或离线检查：

```bash
./dance --showcase --list
./dance --showcase --check
```

单独测试动作时，使用 `./dance 18 --showcase --supported`，也可以把编号换为 `19`、`20` 或 `21`。新版大幅 8 字可直接用 `./dance 20 --showcase --supported` 播放；比较旧版时使用 `./dance 20 --showcase --bundle ../record/dance_showcase/v3 --supported`。更早的 v1/v2 也可通过 `--bundle` 指定。

新版 `21` 默认 1.0 倍、约 16.74 秒，含进入低位和回位。v7/v8 保留原 0.3 倍默认值。`--pivot-speed` 只影响 21。旧 v5 的 6 秒动作保留原默认倍率，旧 v4/v6 保留各自的 30% 默认倍率。

| 输入 | 作用 |
| --- | --- |
| 动作编号 | 播放对应动作，完成后保持位置 |
| `stop` / `estop` | 中止运动，尝试制动并保持 |
| `home` / `quit` | 回零，确认到位后失能退出 |
| `release` | 保护保持中、支撑承重后明确请求失能 |

动作不会自动连播。普通完成后可继续选择编号；保护保持后不再接受新动作，需明确回零或失能退出。软件保持依赖供电、有效反馈和 CAN。

## 动作与节奏

菜单和预览顺序为 `00` → `12`～`21` → `11`。`00` 起身入场和 `11` 慢慢入睡沿用 Daily 的起身、入睡动作；中间十组均从统一互动姿态出发，并回到互动姿态，无需重新录制。

| 编号 | 动作 | 计划时长 | 编排特点 |
| --- | --- | --- | --- |
| `00` | 起身入场 | 4.36 秒 | 从零位起身，进入互动姿态 |
| `12` | 回眸亮相 | 6.67 秒 | 身体先转走，头部反向回望，再划过另一侧回正 |
| `13` | 反向涟漪 | 7.62 秒 | 波峰从肩传到腕，再反送回肩肘 |
| `14` | 弹簧定格 | 6.26 秒 | 压低蓄力、快速舒展，定格 0.22 秒后斜向释放 |
| `15` | 画圈绕场 | 4.72 秒 | 末端按模型规划绕约 8 厘米半径的空间环路，回到原姿态 |
| `16` | 夹爪鼓点 | 6.00 秒 | 两侧交替打短拍，身体横移和抬头配合夹爪 |
| `17` | 谢幕连招 | 8.69 秒 | 回眸、舒展、深鞠躬连续组合，末尾回到互动姿态 |
| `18` | 蛇形波浪 | 7.01 秒 | 同频两周期、肩肘腕逐级错相，波峰沿机械臂传播 |
| `19` | 稳定摇摆 | 7.23 秒 | 底盘左右各摆 35°，腕部三轴补偿末端世界朝向 |
| `20` | 空间 8 字 | 5.10 秒 | 保持约 40×24 厘米双环，采用平滑加减速和巡航进度加快完成 |
| `21` | 大幅定点左右上下 | 16.74 秒 | P 下移 12 cm，准备下倾 10°；左右 ±20°、上下 ±18° 各一次，默认正常速度 |
| `11` | 慢慢入睡 | 4.36 秒 | 从互动姿态收拢回坐姿 |

`12`～`17` 保持原设计，计划时长为 4.72～8.69 秒。每组按 8 拍描述，对应节奏约为 72、63、77、102、80、55 BPM；不是将全部动作强行压成同一个时长。六组手臂峰值速度约为 54～57°/秒，在既有速度、加速度和模型力矩检查内生成；实际效果仍取决于跟踪表现。

`16` 包含两次 **0°→45°→0°的 2 秒短行程**，分别从动作开始后 0.5 秒、3.5 秒起执行，不是 250°全开。物理全开范围与电机零点未改变。`15` 的圆环形状来自 URDF 模型规划，不能将模型轨迹误差当作实机定位精度。

新增三组各有明确的观察重点：

- `18` 蛇形波浪：同一个频率、不同关节相位，让波峰依次沿机械臂传播。两周期贯穿全程，肩、肘、腕相邻相差 60°，并通过包络平滑进入和退出。
- `19` 稳定摇摆：身体摆动时腕部反向补偿，尽量保持末端的世界朝向；末端位置仍会随身体移动，不是悬停在空间同一点。
- `20` 空间 8 字：末端穿过中心、绕出左右双环；原有圆圈仍是 `15`。可以自行安装轻小光源观察光轨，但程序不包含 LED 接线或开关控制，也不假定机械臂已经装灯。

`19` 使用 URDF 逆运动学补偿完整三维朝向；模型中末端朝向基本不变，其左右位置仍移动约 14.2 厘米。`20` 的倾斜 Gerono 8 字保持 v3 的约 40×24 厘米，v4 将全程缓动改为平滑加减速加巡航，缩短慢尾，时长由 8.16 秒减为 5.10 秒；约 2.55 秒穿过中心时保持运动。v2 的小幅 20×11 厘米版本仍保留。尺寸描述倾斜轨迹平面中的整体宽高，不代表三个世界坐标轴各自的行程。上述描述来自计划轨迹，不能作为实机精度保证；新版 `20`、`21` 尚未实机验收。

`18`～`20` 按 8 拍描述，当前分别约为 68.5、66.4、94.2 BPM。v5 的 `21` 也为 8 拍、80 BPM，默认正常速度播放。它显式规定 J1 左右摆动，再由其余五轴进行位置补偿；末端朝向随之变化，不沿用 v4 的规定朝向编排。当前控制周期仍为 50 Hz，不是模板中的 200 Hz。

当前存储用量见对应库 `manifest.json` 的 `json_action_bytes` 与 `compact_motion_json_bytes`。`21` 使用离线逆运动学采样后构建样条，存储量高于单纯参数化动作。这些是本机试播数据，不是最终固件格式，尚未加入 Flash；后续固件集成需单独评估采样压缩与精度，不能直接将这些数字当作最终占用。

## 定格与实际卡滞

有意定格时，计划目标会先平滑减速，保持固定姿态，再进入下一段；它是动作节奏的一部分。若目标仍在连续移动，而实测关节停住后突然追赶，则属于另一类问题，不能用“舞蹈定格”解释。

基础动作的实机日志中出现过低速停住再追赶；最新 v5 记录仍可见 `02` 的 J2 在持续收到运动目标时几乎停住约 0.18 秒。现有数据不足以区分摩擦、重力模型误差和电机闭环响应。本次舞台动作只增加编排设计，不宣称已解决这类实体卡滞。最新审计见 `build/dance-trials/motion-audit-v5-showcase.json`。

2026-11-07 已有一轮用户执行的舞台 v1 试播记录：`build/dance-trials/session-1794046302759140452/summary.json` 中原八组动作全部完成、无报错、无保护停止。该次完整运行不代表上述卡滞问题已经解决，也不包含新增 `18`～`21` 的实机验收。离线关节、速度、加速度和模型力矩检查不等于碰撞验证；工具不会自动驱动 ESP32 屏幕，也不会烧录 Flash。
