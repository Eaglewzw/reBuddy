# 编舞编辑、屏幕预览与机械臂播放

从小屋右下角“设置 → 编排”进入独立编辑页。编舞只使用用户选定的十组舞蹈，日常触摸动作不出现在动作库，也不会作为过渡自动插入。点击编辑页的“播放”，可选择“屏幕预览”或“机械臂播放”；后者会实际驱动机械臂，两种播放暂不同时进行。

## 动作库

| 动作 | 标准时长 |
| --- | --- |
| 点头打拍 | 6.47 秒 |
| 歪头招手 | 6.53 秒 |
| 深蹲回升 | 5.68 秒 |
| 前探伸展 | 3.66 秒 |
| 探头撒娇 | 4.66 秒 |
| 开心欢呼 | 6.53 秒 |
| 蛇形波浪 | 7.01 秒 |
| 稳定摇摆 | 8.74 秒 |
| 空间8字 | 5.10 秒 |
| 大幅定点左右上下 | 16.74 秒 |

动作选择页使用两列图卡，一屏完整显示四个动作，每张卡片显示缩略图、编号、名称和原片时长。上下滑动查看全部十组，停留积木位于最后。“我的编排”同样使用两列图卡：已保存作品展示首个舞蹈的封面、名称、步数和屏幕预览时长，空位显示加号供新建；重建按钮仍需确认，保存前不覆盖原作品。作品内的步骤仍使用列表。可从卡片、卡片间隙或右侧空白区域拖动，滑动不会添加动作。缩略图复用现有动画，分帧解码后独立存入 PSRAM（十张共 120 KiB），离开选择页即释放，不新增 Flash 图片资源。

每个作品最多 8 步，最多保存 10 个作品。每个动作可重复 1–3 次，重复不额外占用步骤。选中步骤后可前移、后移或删除；新增动作插入选中项之后。

“停留”保持当前画面。新建停留默认为一拍，按钮以半拍调整，标准节奏为 300 ms，最大 3 秒；动作结束后停留同样按半拍调整且可为零。旧作品中的 500 ms 等值继续按原时长播放，主动调整后才对齐半拍。开头停留保持自动开场的末帧。

## 背景与节奏

标准节奏保留当前实机动作的原时长，自动开场 5.5 秒、收尾 7 秒；不再把所有片段压为四拍。停留编辑仍以 100 BPM 为基准，慢速按 1.5 倍时长、快速按 0.8 倍时长播放。素材约 12.5 FPS，采用实际逐帧时长；板端实际刷新率仍需实测。

运行资源使用共享 32 色和量化后的 RGBA 覆盖率，复用原 RGB565 房间。动作首尾统一互动姿态，保留已经平滑处理的原轨迹时序，不叠加第二次相位缓动。详细取舍见 [舞蹈优化与机械臂预算](DANCE_OPTIMIZATION.md)。

预览顶部显示动作与进度，下方保留停止。停止和完成均保持当前画面，重播才从开场开始。开场收尾不占步骤，不因停止而强制执行收尾。空作品不可播放，加载或退出不会启动电机。

## 保存与恢复

十个作品槽位使用 NVS 双记录、序号与 CRC 校验。保存时写入较旧记录；写入失败或中断时保留原有效记录。打开、加载与重启均不会自动播放。未保存退出时可保存、放弃修改或继续编辑。

新舞蹈使用 ID 45–54，停留使用 ID 15；43/44 仅用于自动开场收尾，禁止作为手动步骤保存。日常动作 ID 与旧舞蹈 ID 不允许用于编排；包含上一版 ID 33–42 的作品明确提示“旧版作品”，其他已移除动作仍不可播放；旧作品包含这些动作时需要重建，需要明确确认重建并保存，不自动替换或覆盖原内容。加载和保存均执行相同的动作范围校验。

## 机械臂播放

当前 `sdkconfig` 与 `sdkconfig.defaults` 均开启 Daily 和 Dance 控制。正常 `idf.py build` 的 `build/reBuddy.bin` 包含触屏实机入口，不再要求单独构建 `build/dance-c5`。仅构建不烧录、不运动。

操作：设置 → 编排 → 新建或打开作品 → 添加图卡 → 播放 → 机械臂播放。无需先保存即可试播当前编辑内容；保存仍由用户主动点击。

触屏动作 ID 45–54 映射为原生 Dance 01–10，按作品顺序展开每步 1–3 次重复，共用串口播放器的五次多项式衔接、控制任务和 CAN 所有权。慢节奏对应实机半速，标准对应原速；实机快节奏尚未验证，因此拒绝请求并提示选择慢或标准。停留积木与结束停留目前仅用于屏幕预览；实机播放前明确提示移除，不会忽略它们或改变已保存作品。

机械臂从当前实测姿态前往待机后播放，显示实际动作、衔接阶段和执行进度。机械臂时长不使用屏幕预览的开场、收尾与 GIF 时长。完成后持续保持待机，“停止保持”沿用原生制动保持流程，“回零”回零后确认失能。播放中点“返回”先请求停止并停留在控制页，待停止后才可返回编辑。其他控制任务正在运行或保护状态未解除时，新请求会被拒绝；异常反馈和通信故障沿用现有控制器处理。

上电、浏览、添加、加载、保存、屏幕预览均不会提交实机动作。实际测试仍需当前标定、原装配、无额外负载及已有防坠支撑；PC 播放器应已退出，避免并发控制。软件保持依赖有效供电、驱动和反馈。

## 日常界面与硬件边界

进入编排后暂停日常动画、触摸手势与无操作计时；原本休息的桌宠在纯屏幕编辑退出后继续休息。实机 Dance 执行期间禁止 Daily 自动动作，正常 Dance 控制占用和正常回零不作为屏幕故障。编排不会修改 Daily GIF 资源。

图卡触摸滚动、十组选择、保存恢复、屏幕播放、显式实机请求、停止和返回行为有主机测试。真实刷新率、内存峰值、机械臂运动与连续运行仍需板端验收。

资源来源见 [舞蹈资源](../gifs/dance/README.md)，构建与烧录见 [开发指南](GETTING_STARTED.md)。

舞蹈覆盖率直接来自 RGBA 素材。封闭空隙与轮廓透明区域都显示同一位置的小屋背景，白色高光和眼睛保持不透明，不依赖旧素材的颜色种子或专用回转插帧。
