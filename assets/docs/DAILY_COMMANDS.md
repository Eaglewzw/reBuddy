## PC 端直接播放

```bash
cd /home/verser/esp32/reBuddy/tools
./daily --supported
```

进入终端后输入 `01` 平滑到待机，再输入 `02` 抬头看你、`03` 轻蹭、`04` 疑惑歪头、`05` 开心回应。
也可用 `./daily 01 --supported` 启动并直接前往待机；直接选择互动动作时也会先完成待机过渡。
`quit` 回零退出。`--supported` 表示已安装防坠支撑；不要同时运行其他机械臂控制进程。

待机姿态取自 `daily_ready/manifest.json`，Dance 开场 00 复用 Daily WAKE 的六轴路径；
两者启动共用 `Session.connect` 的实测位置过渡。夹爪保留各库已有闭合设定，不改校零。
播放验证当前标定/模型身份、库内 JSON/CSV 校验和、姿态与轨迹端点一致性、关节和动力学约束；
制作时的原始 CSV、`idle.json` 及其哈希仅用于来源追溯，不再成为启动所需文件。

## C5 屏幕带动机械臂

本地联动产物 `build/daily-c5/reBuddy.bin` 及常规构建 `build/reBuddy.bin` 已启用 `CONFIG_REBUDDY_ARM_DAILY_CONTROL=y`；完整烧录参数在该目录的 `flash_args`。本轮没有向设备烧录，也没有发送真实电机指令。

烧录联动固件后的流程：

1. 退出 PC 的 `daily`、录制器、VR 等机械臂控制进程。使用当前已校零的这台 RS 机械臂、CAN1 1 Mbps、ID1～7，以及已安装的独立承重支撑。
2. 上电显示 **SLEEP（熟睡呼吸与 Z）**，程序不发送使能或运动指令。点击左下角旋转箭头（无需长按），程序读取新鲜七轴状态，检查静止与失能状态，再使能、1.5秒渐入重力补偿并执行 **WAKE**，平缓到保存的待机并验证到位。C5 的 WAKE 从新鲜实测位置直接平缓移动到待机，不先回零再播放第二段唤醒。启动画面不代表已经实测确认机械零位。
3. 顶部显示 **IDLE HOLD** 后，原有屏幕触摸手势触发 PROBE、NUZZLE、TILT、HAPPY。已有速度、HAPPY 的90°两次夹爪开合与J1 ±30°连续两个来回保持不变。
4. 待机无操作满60秒或选择休息触发 REST；实际零位稳定到位后进入 ZERO HOLD，随后请求失能；屏幕保持 REST 最后一帧，只有新鲜反馈确认失能后才切换 SLEEP。熟睡画面点击旋转箭头触发 WAKE，重新检查、使能，再返回待机。
5. **屏幕 HOME 或开发板实体 ENTER** 从当前位置回 J1～J6 机械零位，保持夹爪当前开度；实测稳定到位后才请求失能并验证。它不重新写零点。完成后重新显示 SLEEP；熟睡时实体 ENTER 不使能，旋转箭头仍是使能入口。回零中重复按键不会重启回零轨迹；保护减速期间按键会等待恢复流程结束再回零。

实体 ENTER 接法参考 `esp32c5_ui_console/components/can_console_bsp/src/can_console_bsp.c`：PCA9535（I²C地址0x21）的 P0.6，低电平按下。使用本工程现有I²C设备，只读输入寄存器；独立任务约20ms轮询，稳定30ms去抖，一次按下只触发一次。上电已按住或I²C读取失败后，须先稳定松开才接受下一次按下。此处指开发板实体按键，不是电脑键盘或串口换行，也不是硬件急停。

控制任务独立于 LVGL，以20ms周期工作。机械动作和夹爪通过同一组七轴 MIT 指令提交；沿用参考工程的电机服务、RS协议、发送确认和重力模型。屏幕进度跟随已确认发送的轨迹点，完成还需要实测位置/静止验证，TX成功不等于物理到位。CAN繁忙时不会跳过轨迹点追赶屏幕。

启动时不排队补播屏幕操作；运动期间不接受另一动作抢占、反放或突跳。位置已在同一待机目标时省略额外两秒空移动。离开daily进入编舞页会请求回零退出，编舞页本身仍是屏幕预览。

已完成启动后，软件力矩预算超限、运动跟随误差超限、到位超时，以及暂停按钮或UI超过500ms不再更新，进入 `BRAKING → HOLD RAMP → PROTECTIVE HOLD`。HOME 回零的预算/跟随误差超限也进入这条恢复路径。减速时保留全量重力补偿、位置增益为零，阻尼增益按现有力矩预算显式约束；七轴估算速度≤1°/s持续0.5秒后捕获一次保持位置，再用0.5秒恢复位置增益。恢复需按HOME，不自动续播旧动作；恢复期间按HOME会等待该过程结束。过温回零失败进入保持后，不反复自动重试回零。

减速超过5秒仍未静止、保持建立失败、反馈超时、故障位、模式丢失、CAN/发送失败或控制周期超过100ms仍请求失能；启动渐入阶段失败也不进入完整增益的恢复流程。软件温度达到现有100°C阈值且其余反馈正常时请求回零；电机硬件过温故障不强行回零。失能未确认会保留故障与控制权，不宣称已停止承重。日志 `detail` 保留最初原因，`stop_detail` 记录恢复失败或失能未确认的后续原因。屏幕HOME不是独立急停。

顶部显示 `PROTECTIVE HOLD` 时，REST → SLEEP 已暂停，等待不会自动恢复。可能原因包括到位检查超过8秒、估算力矩超过预算、暂停请求或UI心跳超时。C5 的 REST/HOME 回零到位要求J1～J6误差≤3°、J7误差≤3°，七轴估算速度≤1°/s持续0.5秒。不要把保护保持当成“已到零位”。

诊断固件每30秒输出 `rb_daily: snapshot ... detail=...`，串口接入较晚也能看到当前原因；保护触发时的原状态、七轴目标/实测/误差/估算速度会被保留，力矩预算触发还记录估算力矩。后续保持指令不会覆盖这些触发证据。`torque_checked=0` 的记录不提供触发时力矩估算。这项日志补充不改变动作速度、预算或到位阈值；需要烧录新固件才会出现在设备日志中。 C5控制任务的状态日志改为非阻塞快照，由独立低优先级任务输出；输出阻塞时允许合并中间状态，最初触发证据仍保留在状态快照中。

复用来源为 `/home/verser/esp32/esp32c5_ui_console`：`can_console_motor`、`can_console_arm_motion`、`can_console_ik`，参考 `rs_jog_motor.c` 的模式/使能/失能确认流程。电机组件仅增加调用原厂商编码器的状态订阅公开接口；补丁来源与原始校验值登记于 `assets/config/arm_components.json`。

重新构建可联动版本（先加载本机 ESP-IDF 环境）：

```bash
idf.py -B build/daily-c5-control -D SDKCONFIG=build/daily-c5-control.sdkconfig -D 'SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.daily-control.defaults' build
```

也可单独保存上述构建配置；当前根目录默认配置同样已开启联动。机械零点依赖原有电机标定，固件不会自动校零；轨迹/重力一致性测试与模拟故障测试不能替代首次实机联动验收。

## 启动本地终端

先退出录制器及其他机械臂控制程序，在项目目录运行：

```bash
cd /home/verser/esp32/reBuddy
./tools/daily session --supported
```

进入后逐条输入名称或编号，等动作完成再输入下一个：

```text
唤醒
抬头看你
轻蹭
疑惑歪头
开心回应
入睡
熟睡
唤醒
quit
```

不要整段粘贴：运动期间新动作会被拒绝，不排队自动执行；`status` 和退出命令仍可使用。

程序启动时不自动使能；第一次唤醒或互动动作会读取实际位置，使能、渐入重力补偿与位置保持，并慢慢移到待机。动作结束后持续保持待机，等待下一条命令。使能期间不退出进程或停止发送保持指令来“保持使能”。

也可直接指定第一个试播动作，完成后仍停留在同一动作终端：

```bash
./tools/daily play 抬头看你 --supported
./tools/daily play 开心回应 --supported
```

## 退出、检查与日志

`quit`、EOF、首次Ctrl+C或SIGTERM：停止当前动作，用现有VR回零程序回零后失能退出。温度达到已有100°C软件阈值且其他反馈正常，或仅日志/磁盘故障时，也先尝试受校验的回零再失能。软件PD估算力矩超预算按下面的“保护保持”处理；再次中断、反馈故障或其他控制故障仍停止并失能。熟睡时退出不重新使能。机械臂使用已经验证的独立承重支撑。回零/待机必须通过实际反馈的到位检查，不能只等计划时间结束就声称到位。

### 软件力矩超预算时保护保持

`tools/daily play` 和 `tools/daily session` 在已完成使能和增益渐入后，遇到估算力矩超预算、跟随误差超限或到位检查超过8秒，会中止当前动作并执行上述阻尼减速、静止确认和位置保持渐入。按当前七轴预算检查，J7仍为1.5 N·m。减速阶段位置增益为零，位置字段随新鲜实测位置填充；静止后保持目标只捕获一次，不会随着位置漂移不断重设，也不会继续执行被中止动作的后续片段。速度估算采用40ms低通及至少10ms采样间隔；C5用控制采样时刻计算间隔，避免异步状态帧间隔极短放大速度估计。对照测试覆盖相同反馈输入、编码器量化抖动及阻尼预算。

此时 `status` 显示 `PROTECTIVE_HOLD`，新动作被拒绝。`quit` 或首次Ctrl+C仍回零后失能退出。日志记录 `command_rejected`、`protective_hold_requested`、`action_aborted`、`protective_hold_entered`，摘要的 `protective_stops` 保存中止原因和保持目标。进入保持失败时记录 `protective_hold_failed`。

这是受控停止并保持的尝试，不能保证瞬间定住。如果5秒内未停止、保持指令本身仍超预算、反馈失效、重力补偿自身超预算或其他控制检查失败，则仍走故障失能流程。部分使能和增益尚未渐入完成不使用此恢复机制。C5 HOME 的软件预算/跟随误差异常已支持减速保持；Python 的退出回零仍调用原VR回零程序，没有替换其零位补偿或全部内部故障策略。独立 `play_daily` 和录制器不启用daily恢复状态机。已做离线故障注入测试，尚未实机验证。
