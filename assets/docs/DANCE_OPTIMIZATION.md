# 舞蹈播放、衔接与 Flash 预算

本轮针对板端预览优化。屏幕动画与未来机械臂共用动作 ID、事件时间轴和归一化相位；当前不包含已标定机械臂轨迹，不发送 CAN 运动指令。

## 播放与衔接

- 九个高帧率基础动作按 50 ms 采样，标准节奏目标 20 FPS。选帧覆盖源片段的两端，重复画面跨动作复用；帧表有重复项不代表增加了真实运动姿态。
- 十组动作使用同一个中立首尾画面，开场末帧和收尾首帧也连接该画面。自动测试逐像素检查全部 100 种动作连接及重复播放。
- 主体首尾各半拍采用时间重映射：端点速度、加速度为零，连接中段时速度连续。中段继续按原时间运行，避免每次切换瞬间跳姿态。它改善连接，但仍保留“经过中立位”的编舞风格；自由姿态间的连续舞步需要进一步创作素材。
- 标准节奏 100 BPM，一拍 600 ms，基础动作每段四拍（2.4 秒）。开场和收尾的原始素材仍各 3 秒，播放时各占四拍（2.4 秒）。慢速约 67 BPM，快速 125 BPM。
- 新增停留默认为一拍，按钮以半拍（标准 300 ms）对齐。旧作品的 500 ms 等停留值保持原意，主动按加减按钮后才对齐拍点；NVS 格式、动作 ID 和槽位不变。
- 底盘回转原素材只有 16 个姿态，且首尾朝向不同。运行版本从较接近中立的方向开始转身，复用原有转身姿态，加入约 300 ms 的屏幕首尾连接。只对相近的首尾姿态离线做光流连接；转身主体不使用有重影的插帧。其运动流畅度仍受原始姿态数量限制，需要后续补画才能达到其他动作的水平。

## 资源与显示

原始 GIF、日常动画和小屋颜色保留。舞蹈运行资源使用共享 **64 色**索引、16 级轮廓覆盖率；这是为提高时间分辨率并预留机械臂空间做的取舍。色表在每帧转换时新建，避免 Pillow 色表查找缓存影响结果。资源测试限制原始画面减色的平均通道误差小于 4/255，并独立校验解码结果；渐变细节仍需实屏确认。

封闭连杆空隙由 [dance_cavity_seeds.json](../config/dance_cavity_seeds.json) 逐姿态标记，纳入背景遮罩；眼睛和关节高光保留。配置同时校验源 GIF、色表、空隙面积及边界，素材改变时必须重新检查，避免按白色全局删除角色细节。

背景连通区域和边缘覆盖率在电脑上预计算。板端解压索引与覆盖率，再与原始 RGB565 房间合成，不再逐帧做背景洪泛搜索。舞蹈缓存峰值为 614,400 字节（600 KiB），原方案为 921,600 字节（900 KiB）。这只是动画缓存，不包括 LVGL、DMA 或其他堆内存。

日常继续采用独立基准的 RGB565 差分。舞蹈采用有限深度的索引／覆盖率 XOR 差分，最多七层，拒绝向后编号以外的引用、循环和超深链。解码器缓存已恢复的平面，顺序播放通常只需处理下一层；跨动作、倒序、跳帧与损坏回退都须测试。

显示与编舞每 10 ms 检查时间轴；触摸采样与日常行为仍为 20 ms，避免改变有效抚摸累计速度。舞蹈重绘限制在 240×192 可见窗口，静态侧墙无需随每帧传输。`rb_decode` 输出累计平均／最大解码合成时间和失败次数，配合 `rb_display` 判断实际显示负载。资源 FPS 和主机视频不是实测板端 FPS。

## Flash 预算与机械臂接口

配置见 [flash_budget.json](../config/flash_budget.json)。应用分区保持 8,323,072 字节，NVS/PHY 地址不变。动画 blob 上限 5 MiB；整个应用必须至少留下 **2 MiB**：

| 用途 | 暂定预算 |
| --- | ---: |
| 已标定轨迹、姿态、机械臂参数 | 512 KiB |
| CAN 后端、调度与其他代码增长 | 1 MiB |
| 未分配余量 | 512 KiB |

`idf.py build` 和固件打包都会检查完整应用大小，超过预算即失败。预留是构建约束，不是额外分区，也不是对未来全部功能体积的保证；接入真实轨迹后需重新核算。

`rb_motion.h/.c` 提供紧凑关键帧定义与五次多项式过渡计算。六关节、32 个关键帧的基础有效载荷为 `32 × (2 + 6 × 2) = 448` 字节，存储时需要显式编码、版本和校验。应保存经过标定的关键帧与约束，运行时插值，而不是保存每个控制周期的全量角度。

连接轨迹可从确认后的实际起始姿态与目标姿态计算，避免为 N 个动作保存 N² 份轨迹。当前函数检查关节位置、速度及加速度约束，并计算所需时长；它不检查碰撞、负载、力矩或机械臂协议。实体后端接入前还必须验证这些条件，并在过渡需要延长时重新安排屏幕与实体的共同时间轴。屏幕光流和像素坐标不得用作关节角度。

## 验证与样板

主机测试包含逐帧 CRC、独立解码、所有首尾组合、半拍编辑、旧存储兼容、有限链跳转／损坏回退、运动过渡约束和 Flash 超限检查。

`rebuddy_dance_preview` 使用实际 C 编排核心与资源解码器输出 14.4 秒 RGB565 样板：开场、点头、大幅摇摆、点头、大幅波浪、收尾。构建主机目标后：

```bash
build/host/rebuddy_dance_preview build/host/dance-preview.rgb565
ffmpeg -f rawvideo -pixel_format rgb565le -video_size 320x240 -framerate 20 \
  -i build/host/dance-preview.rgb565 -c:v libx264 -pix_fmt yuv420p build/host/dance-preview.mp4
```

上板时先用标准节奏比较该样板，再检查底盘回转、快慢节奏、停止／重播、摸爪累计和内存最低余量；完成连续 30 分钟验证。本轮构建与主机结果不能替代这些实机验收。


控制基础组件现已集成，启动和监听接口见 [HARDWARE.md](HARDWARE.md)。当前 `rb_motion` 六关节过渡函数仍只处理运动学关节；未来动作数据必须额外包含夹爪通道。上游 TCH1 v2 作为导入参考，不等于已选定的稀疏舞蹈格式：它要求相邻样本最多 100 ms，且 `int16 × 0.0001 rad` 的编码范围不能覆盖 RS 模型第三关节的整个 200° 范围。实际导入须校验并明确拒绝无法表示的数据，不能截断或静默更改原单位。
