# 网页端动画素材制作任务

目的：使用指定角色原图与互动示意图制作真实的身体动作连续帧，供 ESP32-C5 屏幕播放。当前不涉及实体机械臂控制或编舞。

## 上传材料与制作顺序

首次对话上传两张原始 PNG：

1. `character_reference.png`：角色外形、材质、眼形的最高优先级依据。
2. `interaction_storyboard.png`：六种身体动作与情绪的依据。

先生成并确认一张512×512的待机基准图。后续每段动作都附上这张基准图和相关原图，要求严格延续角色。每次只生成一段动作；不要让模型一次绘制所有动作。

优先完成：待机基准 → 探头 → 退缩 → 开心 → 入睡。四段动作确认后，再制作轻蹭、安抚恢复、唤醒、好奇歪头。动画文件需要原始PNG，不使用聊天截图、JPEG或GIF作为源素材。

## 第一步：待机基准图提示词

```text
请依据我上传的两张原图，制作同一只 reBot 机械臂桌宠的动画基准图。

图1 character_reference.png 是角色外观基准，优先依据其中左侧的大角色：黄绿色外壳、黑色机械连杆、银色圆形关节、黑色前置夹爪、宽而矮的固定基座。保留同一套机械结构、原图的可爱比例、三分之四视角、光照、材质与描边。可见结构包括基座上方的肩关节、中段肘关节、头部侧面的腕部圆盖，所有后续动作保持这套结构；遮挡可以改变，零件不可凭空增减。

保留原图黑色面屏上的发光浅绿色大眼睛、弯月状眼形与高光、眉弧和粉色短线腮红。不要改成简单的两个小圆点或通用机器人表情。图2 interaction_storyboard.png 用于理解同一个角色的身体和夹爪结构，不画成拼图。

生成一张512×512的PNG，只有一只完整角色，无文字、标志、动作线、感叹号、手指或道具。背景为均匀纯色 #F8F7EF，无渐变、无地面场景、无投影。角色处于放松待机姿态，夹爪轻合。

构图供后续逐帧动画使用：基座左右居中，中心线x=256，基座底缘y=476，基座宽约220像素。完整角色在画面内，四周至少留16像素。保持角色自然比例，不为填满画面拉伸或加大头部。相机、基座和光照将在所有动画帧中固定。

请直接生成图片，不添加说明文字到图片里。
```

保存为 `00_idle_master.png`。先检查造型是否正确；若基准图已经偏离原图，应先修正这张，不继续生成其他动作。

## 第二步：每段动作都附上的公共提示词

每次上传 `00_idle_master.png`，并附两张原始参考图。复制下段公共提示词，再追加对应动作段落。

```text
请制作 reBot 机械臂桌宠的一段连续动画精灵图。

已上传的00_idle_master.png是这段动画的角色、镜头、基座、比例和材质基准；character_reference.png限定角色外观与原画表情；interaction_storyboard.png限定动作姿态。严格保持同一角色，不重新设计。

输出一张PNG精灵图，4列×3行，共12个等大的正方形帧。目标尺寸2048×1536，每格512×512；若无法输出该分辨率，优先保持4:3画布比例、严格4×3等分网格和相同帧尺寸，并告知实际尺寸。顺序为从左到右、从上到下，按这个顺序播放。不要画网格线、边框、帧编号、文字或分隔装饰。每格背景是均匀 #F8F7EF，格与格之间没有留白边距。

每格只画一只完整角色。基座中心线x=256、底缘y=476、宽约220像素（坐标相对当前格，实际尺寸不同时等比换算）。每帧基座形状、尺寸、位置和朝向完全一致，相机和光照固定。不允许角色整体漂移、整体缩放或背景变化。趴低时角色应真的变矮，不把睡姿放大到站立高度。夹爪和头部始终在当前格内。

通过明确的肩、肘、腕关节转动产生动作；刚性连杆与银色圆形关节保持形状。动作中只改变关节姿态与真实遮挡关系，不得像橡皮一样拉伸身体，零件不可增减。夹爪是同一对机械夹指，开合保持连接与体积。

需要连续且不同的中间姿态，每两帧之间的关节变化小而平顺，进入和结束逐渐减速。除必要的起点/终点与停留外，至少8张不同姿态。不要重复同一张静态图充数，不使用重影、叠化、残影或运动模糊模拟动作。

保留参考图的眼形、高光、眉弧和腮红，面部表情随动作自然变化。眼睛随脸部透视移动，始终贴合面屏。当前请把完整表情直接画在每帧中，不额外叠加第二套眼睛。无文字、气泡、问号、感叹号、汗滴、睡眠字母、动作线、手指、道具或地面投影。

下面是这一段的具体动作要求：
```

12帧是素材数量，播放时长与关键帧停留由程序控制。动作的时间节点以资料包为准；网页生成时优先保证连续姿态和结构正确。

## 01 探头 PROBE

```text
动作：轻点后探头。依据interaction_storyboard.png的01“轻点·探头”。
第1帧严格匹配00_idle_master。
第2～5帧：目光转向画面右前方，肘关节逐渐打开，上段连杆伸展，头部和夹爪一起向右前方靠近。表现真实的前探轮廓，不能只是脸在原位置移动。
第6帧：到达与示意01相符的探头姿态，睁大眼睛好奇观察。
第7～11帧：沿同一套关节结构逐渐收回，速度在结束时放缓。
第12帧严格回到第1帧的待机姿态。
底座始终固定，夹爪轻合，不突然变成长脖子。
```

保存：`01_probe.png`。代码目标基础时长1200ms。

## 02 轻蹭 NUZZLE

```text
动作：被温柔抚摸时轻轻蹭蹭。依据示意02“抚摸·蹭蹭”。
第1帧严格匹配00_idle_master。
第2～4帧：眼睛逐渐变为参考图中的弯眼笑，腕部和肘部协同转动，让头部向一侧靠，身体形成示意02的温柔侧靠姿态。
第5～8帧：经过中间姿态，向另一侧轻轻蹭过去。头部、连杆和夹爪共同跟随，底座不移动。
第9～11帧：减速回到正中。
第12帧的身体严格匹配第1帧，保持放松的原画弯眼表情，方便连续轻蹭。
这是缓慢轻柔的一轮摆动，不是抖动、跳跃或整张图旋转。
```

保存：`02_nuzzle.png`。基础周期1000ms，开始/结束的表情由播放器处理。

## 03 退缩 WITHDRAW

```text
动作：被连续戳动后向内收拢。依据示意03“连续戳·缩回”。
第1帧严格匹配00_idle_master。
第2～3帧：眼睛短暂睁大，显得受惊和迟疑。
第4～9帧：肩、肘和腕部连贯折叠，上段向基座方向收回，头部降低并向内靠，夹爪收到脸前。应呈现示意03的内收轮廓，不能只是整个角色缩小或后移。
第10～12帧：收拢姿态逐渐停稳，保持略紧张、避视的表情。最后一帧是将长期停留的稳定退缩姿态，不返回待机。
不要画汗滴、惊叹符号或运动线。
```

保存：`03_withdraw.png`。基础时长900ms。请另存最后一格为 `03_folded_master.png`，后续安抚必须从这张开始；若网页无法精确裁切，可以只保留原始整张图，由工程端提取最后一格。

## 04 安抚恢复 RECOVER

额外上传 `03_folded_master.png`，或明确指定 `03_withdraw.png` 的最后一格作为起点。

```text
动作：收拢后被安抚，逐渐展开靠近。依据示意04“安抚·靠近”。
第1帧严格匹配已上传的稳定退缩姿态03_folded_master，不从普通待机开始。
第2～3帧：眼神先放松，身体仍收拢。
第4～8帧：肘部逐渐打开，头部和夹爪温柔向前靠近，形成示意04的展开姿态。
第9～10帧：轻轻侧靠一下，配合柔和弯眼。
第11～12帧：身体减速回到00_idle_master的待机姿态。最后一帧身体与基准一致，表情温柔明亮。
不要直接切换到开心抬身，不跳跃、不突然弹开。
```

保存：`04_recover.png`。基础时长1600ms。

## 05 开心 HAPPY

```text
动作：持续温柔抚摸后开心。依据示意05“持续抚摸·开心”和character_reference.png的开心姿态。
第1帧严格匹配00_idle_master。
第2～4帧：原图式弯眼笑渐渐出现，肩肘展开，上段身体抬高，头部和夹爪随之升起。
第5～8帧：保持舒展的开心姿态，轻轻左右摆一轮；夹爪平顺张开一次再合回，保持同一对夹指。动作高点要具有示意05的挺起身体和张爪轮廓。
第9～11帧：上段逐渐落回待机，表情仍满足。
第12帧身体严格回到00_idle_master，夹爪回到原开合程度。
底座不离地，不跳跃，不整图上下移动。不添加爱心、彩纸、字母或动作线。
```

保存：`05_happy.png`。基础时长2000ms。

## 06 入睡 REST

```text
动作：困倦后低头收拢入睡。依据示意06“无操作·瞌睡”以及character_reference.png的困倦姿态。
第1帧严格匹配00_idle_master。
第2～4帧：眼皮渐渐下垂，头部开始下沉。
第5～9帧：肩、肘和腕部逐渐折叠，头部降低到靠近基座，夹爪随腕部放低，形成与示意06一致的趴低轮廓。
第10～12帧：低矮收拢姿态停稳，眼睛合为原图式柔和闭眼弧线。最后一帧是稳定睡姿，不返回待机。
睡姿高度明显低于站立；基座尺寸不变。不画“Z”、字母或符号。
```

保存：`06_rest.png`。基础时长3000ms。最后一格作为 `06_sleep_master.png`，用于唤醒起点。

## 07 唤醒 WAKE

额外上传 `06_sleep_master.png`，或指定 `06_rest.png` 最后一格作为起点。

```text
动作：从同一稳定睡姿醒来。
第1帧严格匹配06_sleep_master。
第2～3帧：保持低矮身体，眼睛迷糊地半睁。
第4～9帧：肩肘缓慢展开，头部和夹爪逐渐抬起，恢复正常身高，眼神逐渐明亮。
第10～12帧：动作放缓，回到00_idle_master的相同待机姿态和表情。
这是睡姿到待机的连续展开，不是把睡姿整体向上平移或放大。
```

保存：`07_wake.png`。基础时长1600ms。

## 08 好奇歪头 TILT

```text
动作：受到快速划动后好奇歪头。表情和倾头意图依据character_reference.png中的“好奇”。
第1帧严格匹配00_idle_master。
第2～5帧：睁眼注视，腕部带动头部向一侧倾斜，肘部做小幅配合，夹爪随腕部保持连接。
第6～7帧：倾头观察，保留原图的好奇大眼睛与视线偏移。
第8～11帧：逐步回正。
第12帧严格匹配00_idle_master。
保持基准图的整套关节结构，不直接换成小图中不同透视或不同可见关节的另一只角色；不让底座一起倾斜，不添加问号。
```

保存：`08_tilt.png`。基础时长1000ms。

## 基准待机眨眼（可在主体动作确认后补充）

```text
使用00_idle_master，身体、基座、光照和夹爪完全保持不动，制作12帧自然眨眼精灵图。
第1～4帧保持原画睁眼，第5帧半闭，第6帧闭合，第7帧半开，第8～12帧恢复同一睁眼表情。
只改变眼皮与眼形；保留原图眼睛光色、高光、眉弧和腮红，不改变面屏轮廓或角色几何。遵守公共提示词中的4×3布局、背景、格内尺寸和落点。
```

保存：`09_idle_blink.png`。

## 交回工程端

将生成的原始PNG保存到：
`assets/design/<动作名称>/`

保留失败版本时添加后缀，不覆盖已经确认的基准图。可先只保存基准图和探头精灵图，然后通知开发助手检查。

工程端负责：核对12格分割与真实尺寸、检查原图造型及关节一致性、统一落点、逐帧预览、裁切与RGB565转换、帧去重与预算、接回状态机、构建和性能验证。如果网页没有输出严格网格或角色跨格，先返工，避免靠裁切掩盖素材错误。

原画表情已烘焙进帧，初次接入必须关闭旧独立眼睛叠层，避免双眼重影。后续确有需要再基于确认素材分离干净面屏与原画眼睛；不重新设计一套简化眼睛。

原始素材要求不只是像素格式正确；先确认视觉，再处理工程格式。不要求网页提供C代码、电机参数、真实关节角度或硬件配置。
