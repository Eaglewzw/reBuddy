# 12 组机械臂舞蹈试播

这套数据根据现有 12 组 Dance GIF 的动作含义设计，使用当前标定和 Daily 的统一互动姿态。默认版本为 `record/dance_designed/v6/`（`fast_v6`）：加快基础舞蹈并减少动作内部的慢段，不放宽手臂速度、加速度或力矩预算。`00` 开场、`11` 收尾仍沿用 Daily 定位速度；旧版 v5 数据保持原样。

## 启动与操作

已安装可承重的防坠支撑、留出动作空间后，在本机终端运行：

```bash
cd /home/verser/esp32/reBuddy/tools
./dance --supported
```

输入一个编号播放一组，等待完成后再选下一组，不自动连播。

这里的“连续”指单组动作内部不插入固定停顿。逐组试播完成后仍保持位置，等待下一编号。

| 输入 | 含义 |
| --- | --- |
| `00`～`11` | 播放对应动作 |
| `stop` / `estop` | 中止当前运动，尝试制动并保持位置 |
| `home` / `quit` | 回零，确认到位后失能退出 |
| `release` | 支撑承重后明确请求失能 |

普通播放完成后保持力矩，可继续输入下一编号；故障保持后不再接受动作编号，需明确回零退出或失能，不会自动恢复动作。软件保持依赖供电、有效反馈和 CAN，无法保持时仍需防坠支撑承接。

也可以直接指定一组：

```bash
./dance 01 --supported
```

只查看目录或检查数据，不连接机械臂：

```bash
./dance --list
./dance --check
```

需要对比保留的 v5 时，在同一 `tools` 目录显式指定版本：

```bash
./dance --bundle ../record/dance_designed/v5 --list
./dance --bundle ../record/dance_designed/v5 --supported
```

## 动作编号

| 编号 | 动作 | 编排用途 |
| --- | --- | --- |
| `00` | 开场 | 复用 Daily 起身，从零位来到互动姿态 |
| `01` | 点头打拍 | 肩肘保持互动姿态，腕部轻点接深点，连续回中 |
| `02` | 抬臂舒展 | 肩肘大幅上提，腕部延迟打开，沿弧线连续收回 |
| `03` | 深蹲回升 | 连续两次下沉、弹起，肩肘反向配合 |
| `04` | 前探伸展 | 向前展开，头部左右掠过，再连续收臂 |
| `05` | 底盘回转 | 底盘连续扫过左右，肩肘只做一次配合支撑 |
| `06` | 大幅摇摆 | 一轮大幅侧摆配合肩肘起伏，头部反向 |
| `07` | 折肘展开 | 在大幅收拢与展开之间连续穿行，肩腕配合 |
| `08` | 抬头俯看 | 抬头、侧看、俯看沿弧线连续衔接 |
| `09` | 夹爪开合 | 六轴不动，J7 执行 0°→45°→0°短行程快拍，不是 250°全开 |
| `10` | 大幅波浪 | 肩肘腕传递一轮相位波，保留各轴摆幅，底盘、侧倾错拍呼应 |
| `11` | 收尾 | 复用 Daily 慢慢入睡，回到零位 |

`01`～`10` 首尾均为统一互动姿态，供后续组合衔接。`00` 和 `11` 是起身与收尾，不需要额外录制。v6 的内部运动连续，不安排固定定格；自然换向仍会减速。首尾按 C2 收束，位置、速度和加速度连续到静止，不把首尾描述为 C3。

| 动作 | 保留的 v5 时长 | 默认 v6 时长 | v6 节奏 |
| --- | --- | --- | --- |
| `00`、`11` | 各 4.36 秒 | 各 4.36 秒 | Daily 定位不提速 |
| `01` | 8 秒 | 4.65 秒 | 8 拍 / 约 103 BPM |
| `02` | 10 秒 | 3.52 秒 | 8 拍 / 约 136 BPM |
| `03` | 10 秒 | 5.68 秒 | 8 拍 / 约 85 BPM |
| `04` | 10 秒 | 3.66 秒 | 8 拍 / 约 131 BPM |
| `05` | 10 秒 | 5.30 秒 | 8 拍 / 约 91 BPM |
| `06` | 10 秒 | 5.53 秒 | 8 拍 / 约 87 BPM |
| `07` | 10 秒 | 3.89 秒 | 8 拍 / 约 123 BPM |
| `08` | 10 秒 | 3.88 秒 | 8 拍 / 约 124 BPM |
| `09` | 2 秒 | 2 秒 | 2 拍 / 60 BPM |
| `10` | 10 秒 | 4.54 秒 | 8 拍 / 约 106 BPM |

提速以规划曲线的实际速度、加速度极值为约束，`06`、`10` 减为一轮相位波，保留 v5 的各轴摆幅。`09` 仍只驱动 7 号电机、六轴保持待机，使用单条 2 秒曲线执行 0°→45°→0°，去掉 v5 中间的 0.1 秒固定停留。45°仍是短行程目标，不是物理全开位置；250°物理范围和旧版完整开合数据均保留。

J7 的规划预算仍为 1.6 rad/s、5.1 rad/s²，v6 曲线峰值约为 1.349 rad/s、4.712 rad/s²；运动中的 10.8°跟踪窗口、1.5 N·m 力矩预算、KP/KD 均未改变。v6 新轨迹只完成离线验证，尚未实机验收。

用户确认旧版 `09` 报告 J7 +4.496°时夹爪已物理闭合。因此仅在 **J7 目标为 0°且目标速度为 0** 的闭合状态，使用 6°到位容差，并允许相应的临时闭合保持误差；仍要求估算速度不超过 1°/秒并稳定 0.5 秒。非零夹爪目标仍使用原到位要求，六轴容差不变。目标仍是绝对 0°，没有把 +4.496°写成新零点，也没有重设电机零点。

2026-11-07 的 v5 完整试播记录中，12 组动作全部完成，无报错或保护停止；但最新审计仍可见 `02` 的 J2 在目标约 2.53°/秒时，0.18 秒内实际仅移动约 0.012°，期间控制命令仍持续发送、周期约 20 毫秒。这种低速停住再追赶与规划定格不同，不能把一次完整播放当作卡滞已解决。

现有耦合动作数据不足以可靠区分摩擦、重力模型误差和电机闭环响应。v6 的提速与连续性是规划数据改动，不宣称根治实体卡滞，也不据此猜测控制增益或摩擦补偿。最新证据保存在 `build/dance-trials/motion-audit-v5-showcase.json`，分析脚本为同目录的 `audit_recent_motion.py`。v6 仍需实机验证。

v5 与 v6 的逐组时长、计划速度、低速区间和 jerk 对比保存在 `record/dance_designed/v6/motion_review.json`。提速会增加部分曲线的有限 jerk 峰值；“连续”不等于所有导数都更小。这些是计划轨迹的计算结果，不是实机跟踪测量。

存储使用关键姿态和曲线参数，不保存整段高频采样。v6 的 12 份动作 JSON 合计 55,453 字节，加清单共 62,439 字节；纯运动段的紧凑 JSON 为 13,273 字节。独立分析报告 `motion_review.json` 为 33,834 字节，不属于运行必需的动作数据。这些尚不等同于最终固件占用；原始录制、旧版本、GIF 和诊断日志独立保留。

这套动作是新设计的试播数据，不代表已实机验收。首次逐个查看效果后，再决定各动作的幅度、节奏和停顿是否需要调整。当前试播入口不驱动 ESP32 屏幕，也不将数据烧录到 Flash。

## 离线骨架预览

```bash
cd /home/verser/esp32/reBuddy
/home/verser/Python/lerobot/.venv/bin/python -B tools/render_dance_design.py --library record/dance_designed/v6 --output build/dance-design-preview/v6 --fps 20
```

输出到 `build/dance-design-preview/v6/`，动画采用 20 帧/秒；原有 v5 预览保留：

- `contact-sheet.png`：12 组动作的代表姿态，灰线为各自起始姿态。
- `00.gif`～`11.gif`：每组关节骨架动画，包含时间进度。
- `index.json`：预览索引和模型校验值。

预览依据 URDF 正向运动学绘制关节与末端方向，没有实体外壳、桌面或碰撞几何，不构成碰撞验证。模型中的夹爪手指是固定关节，预览只显示 J7 电机角度，不虚构夹爪张口尺寸。
