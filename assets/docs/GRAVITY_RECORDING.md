# RS 本地重力补偿示教录制

**实机录制入口已恢复**：2026-10-31 用户确认已安装并验证能独立承重的支撑，并明确要求删除事故后添加的录制锁。使用 `record --supported` 在交互终端启动。正常输入 **`quit` 或第一次 Ctrl+C 会先将 J1～J6 回到机械校零位，验证稳定到位后失能退出；夹爪保持开度**。反馈、力矩、标定及超时检查仍保留；故障、回零失败或中断时仍由外部支撑承接失能。该功能只通过离线测试，不代表间歇反馈问题已修复，详见 [本次异常记录](RS_GRAVITY_RECORD_INCIDENT.md)。

入口：`tools/record_daily`。用于 PC + SocketCAN 的 reBot B601-RS 实体机械臂拖动示教，录制六轴和夹爪实测位置。六轴采用重力补偿与阻尼，夹爪保持启动时的实际开度；本版不录制手动夹爪开合。

底层复用本机 `/home/verser/Python/lerobot-teleoperator-rebot-vr/` 已安装的 Python 包：`RSConnection` 管理 motorbridge 连接、电机身份、七轴并发参数读取及句柄关闭；`B601GravityCompensator` 提供 Pinocchio 重力计算。控制报文仍通过 motorbridge 的 `send_mit()` 发出，不自行编码 MIT 控制帧。本项目只适配录制流程、边界校验和既有承重退出策略。

额外的原始 CAN 诊断、接收时间戳核验及独立进程失联停机目前仍保留：motorbridge 0.5.3 的 `get_state()` 不提供接收时间戳，参考项目也明确不以缓存读取时间证明反馈新鲜或失能成功。这些附加功能不应被误认为 VR 程序原本就有。参数负载异常尚未定位前，不通过删除诊断核验宣称故障已修复；诊断程序的手工解码器不替代 motorbridge 的运动指令通道。

2026-10-31 已完成离线测试与 mock 录制，**未完成本工具的实机通电验收**。用户最新确认支撑可实际承接全部电机失能后的机械臂重量；尚未提供 J4 异常反馈的具体修复证据。它不修改既有播放器，也不自动回放新录制。

## 启动

在 reBuddy 项目根目录打开交互终端：

```bash
# 默认操作，不打开 CAN；检查 Python、驱动版本、标定身份与动力学模型
./tools/record_daily check

# 无硬件模拟录制，验证日志、片段和 CSV 输出
./tools/record_daily mock --seconds 3 --name idle_demo

# 只读硬件诊断：保持电机未使能、机械臂由外部支撑承重
# 比较 SDK 读数与原始 CAN 回包，不使能、不发送力矩/位置目标、不写零
./tools/record_daily diagnose --seconds 30 --read-mode parallel
./tools/record_daily diagnose --seconds 30 --read-mode serial
./tools/record_daily diagnose --seconds 30 --read-mode raw

# 实机：已固定底座、安装防坠支撑，退出/故障失能后由支撑承重
./tools/record_daily record --port can0 --supported
```

实机模式会使能电机并施加重力补偿。请使用已经验证的同一机械结构、安装方向与负载；本版使用底座竖直、标准夹爪模型，没有额外工具负载项。保持当前标定，不在会话中写零。CAN 使用当前项目的 can0 / 1 Mbit/s 配置，程序不会更改接口速率；参考仿真项目的 500 kbit/s 示例不应直接覆盖现场配置。关闭其他会向同一机械臂发命令的程序。

状态上报策略：启动检查期间临时开启周期主动上报；看门狗启动等待、模式设置及逐轴使能过程中持续读取独立接收器，避免启动回包积压；使能确认后通过 motorbridge 关闭额外周期上报，控制期间检查每次 MIT 指令的状态回复。SDK 位置仍与独立原始参数回复核验，并保留状态新鲜度、模式、故障和温度检查。此调整针对 20261031T104937Z 会话同时存在 100 Hz 主动上报、50 Hz 控制回复及异常位置负载的现象，尚未实机证实能消除异常；详见 `RS_GRAVITY_RECORD_INCIDENT.md`。

默认 Python 为 `/home/verser/Python/lerobot/.venv/bin/python`，可用 `REBUDDY_PYTHON` 指定其他环境；需要 NumPy、SciPy、packaging、Pinocchio、motorbridge `>=0.5.3,<1` 和用户提供的 `lerobot_teleoperator_rebot_vr` 包。不需要 MuJoCo Viewer、摄像头或 VR 设备。

`diagnose` 不加载重力模型，不使能或失能电机，不输出控制目标；它请求位置参数并临时订阅状态报告，要求反馈显示未使能。日志写入 `build/record-review/feedback-audit-*.jsonl` 和对应摘要 `.json`，保存 SDK 原值（即使明显越界）和原始回包。`parallel` 对照原读取方式，`serial` 逐轴读取；`raw` 绕过 SDK 参数缓存，直接发送 0x7019 读取请求，检查电机 ID、寄存器、主机 ID、读失败标志与新鲜时间戳。raw 模式的 `sdk_compared=false`，不宣称做了 SDK 对比。一次无异常不等于间歇问题已经修复，也不构成实机录制验收。

默认读取当前 LeRobot 标定文件和与之绑定的六轴 URDF。可使用 `--calibration`、`--urdf` 指定其他路径，但模型 SHA-256 必须与标定一致；完整七轴标定及电机 ID/型号也必须匹配。校零回读接近零不等于已经证明机械零位与模型零位一致，重力补偿使用与当前参考控制器相同的原始电机→模型恒等映射。

## 先设置共用待机姿态

抬头、轻蹭、歪头和开心回应共用 `ATTENTIVE` 待机姿态作为起点和终点。眨眼由屏幕表现，机械臂保持这一姿态。电机零位不等于待机姿态。

**已有有效待机预设时，实机录制启动会先回机械零位，再到待机。** `record --supported` 读取当前七轴角度，在使能前检查两段路径及重力预算：当前位置→J1～J6零位（夹爪保持当前开度），零位→保存的七轴待机预设（包括夹爪保存的开度）。使能后在当前位置渐入保持与补偿，先回零，采用已加载 VR 配置的 `exit_zero_tolerance_deg`（当前2°），且估算速度≤1°/秒持续0.5秒后再向待机运动。待机到位仍要求误差≤1°、估算速度≤1°/秒持续0.5秒。待机稳定到位后，用约1秒逐渐撤掉六轴位置增益和 MIT 阻尼，持续重力补偿并接入示教阻尼。看到“可拖动录制”后输入 `start 名称`。这些过渡不计入动作 CSV，提前输入 start 会被拒绝，不延后自动执行。回零是受控运动，不重写编码器零点或标定。

零位附近读数可能略低于模型下限。自动过渡允许首个实测位置在既有±3°测量容差内，以该真实读数作为起点；轨迹范围仅扩展到这个起点，不能继续向限位外运动，最终目标仍必须位于原模型限位内。这样消除了旧0.1°曲线余量与3°反馈容差的冲突，而不是将全部目标限位放宽3°。位置保持控制使用同一起点范围，原始读数不截断、不改零。该入口检查同时用于 CSV 播放与自动补回待机。

会话摘要的 `startup_zero_requested`、`startup_zero_completed` 单独记录启动回零；原 `zero_return_*` 仍表示退出回零。`stop` 后的补回动作直接去该片段的待机预设，不经过零位；`--manual-start` 跳过自动启动回零及自动到待机。

该功能复用 `rs_gravity_play.prepare_entry` / `Controller` 与 `rs_gravity_record.Control`，不另建 CAN 控制通道。自动移动不包含碰撞检测或避障，启动前需确保路径和夹爪开合空间可用。过渡期间 Ctrl+C、quit、EOF 或 SIGTERM 仍可结束会话并回零；反馈故障或未稳定到位则中止，不能进入拖动录制。会话时限从切换就绪开始计算。

已核对 `record/gravity/20261031T112755Z-1793446075081499801/idle.csv` 为完整实机待机录制，其姿态与现有 `presets/idle.json` 一致（六轴平均偏差最大约0.012°），因此直接复用这个预设，不替换原文件或片段。每次启动都会使用当前标定下的有效预设，而不是扫描并猜测最新 CSV。

第一次没有预设时，沿用手动设置流程。需要跳过自动到位、重新设置姿态时可运行：

```bash
./tools/record_daily record --supported --manual-start
```

重力补偿就绪后，手动摆好待机姿态，稳定保持至少 1 秒，输入：

```text
pose idle
```

工具检查最近约 1 秒的七轴反馈连续，且每轴波动不超过 0.5°，取平均值作为预设。保存到 `record/gravity/presets/idle.json`，绑定本次标定和模型 SHA-256；下一次默认启动自动载入并移动到该姿态。mock 使用独立的 `idle.mock.json`，不能作为实机预设，且不会执行自动到位。

保存操作只记录姿态，**不会锁住机械臂，也不会自动移动到待机**，重力补偿继续。文件由后台保存，看到“待机预设已保存”后再开始动作录制。已有预设需要调整时，结束当前片段后输入 `pose idle replace` 明确替换；先前片段仍保留录制时的原预设，不被新值覆盖。

`status` 会显示当前七轴与待机的角度偏差。动作起点要求每轴距离预设不超过 2°，这是手动录制的对齐检查，后续仍需拟合与验证精确的共用轨迹端点。

| 动作命令 | 开始要求 | 实机 `stop` 行为 |
| --- | --- | --- |
| `start idle` | 位于待机 | 自动补回待机后结束 |
| `start probe` | 位于待机 | 自动补回待机后结束 |
| `start nuzzle` | 位于待机 | 自动补回待机后结束 |
| `start tilt` | 位于待机 | 自动补回待机后结束 |
| `start happy` | 位于待机 | 自动补回待机后结束 |
| `start rest` | 位于待机 | 可结束于休息姿态 |
| `start wake` | 从实际休息姿态开始，本版尚未保存/检查休息预设 | 自动补回待机后结束 |
| `start sleep`（可选） | 手动确认位于休息姿态；目前为自由录制，不自动检查休息位置 | 保持休息姿态后停止 |

支持 `probe_2`、`happy-3` 等重复录制名称，沿用同一动作规则；自定义其他名称作为自由录制，不自动约束首尾。除自由录制的 `sleep` 外，上表命名的动作都需要先保存有效待机预设。

熟睡实体首版不做周期起伏，因此通常不必单独录 `sleep`，使用入睡终点保持即可。`sleep` 自由录制例外，不要求待机预设。待机眨眼和 Z 均不是机械臂关节动作。

如果起点不匹配，仍拒绝开始片段并显示偏差。实机录制上述需要待机结尾的动作时，`stop` 以当前实测姿态结束手动段，不再要求用户手动精确回位：先保持结束姿态并逐渐接入位置控制，在控制循环内分批校验回位路径的重力预算，然后平滑补回该片段开始时绑定的待机预设，确认到位并切回重力补偿后才完整结束片段。回位使用同一运动规划/控制器，不重新开启 CAN 连接，也不暂停心跳进行完整路径计算。

自动补回的实测采样连续写入同一个 CSV，播放会包含该段动作；`summary.json` 增加 `manual_end_ns`、`manual_end_rad` 和 `auto_return`，区分手动终点与完整动作终点。启动时自动到待机不录入片段，stop 后的自动回位则录入。自动回位期间重复 stop 只显示进度，start 被拒绝；quit/Ctrl+C 会按既有策略回零退出，但中断的片段标为不完整。反馈故障、回位未到位或存储故障也不能把片段标为完整。`rest` 和自由录制保留原终点，不强制补回待机。重新校零或模型变化时旧预设不能直接复用，需要重新设置。

## 录制基础素材

启动时持续支撑机械臂，补偿用 1.5 秒渐入。看到“就绪”后，在终端输入命令，每条按 Enter。`start` 前的摆姿态过程不会进入该片段。

| 命令 | 手动操作 | 结束 |
| --- | --- | --- |
| `start idle`（可选） | 在已保存的互动待机姿态保持约 3 秒；预设本身已由 `pose idle` 保存 | 输入 `stop` |
| `start happy` | 待机停 2 秒 → 肩肘慢慢舒展 → 停 2 秒 → 回待机 → 停 2 秒 | 输入 `stop` |
| `start rest` | 待机停 2 秒 → 慢慢收拢低头 → 进入有支撑的休息姿态 → 停 3 秒 | 输入 `stop` |
| `start wake` | 从同一休息姿态停 2 秒 → 缓慢展开抬起 → 回待机 → 停 3 秒 | 输入 `stop` |

对需要待机结尾的动作，输入 `stop` 后请停止拖动并让出自动回位路径，等待“已自动补回待机，片段完整结束”；此后重力补偿继续，可以 `start 新名称` 录下一个动作。对 `rest` 和自由录制，stop 直接结束片段、补偿继续。stop 不结束会话，不执行机械回零或失能。名称仅支持英文、数字、下划线和短横线，单个会话不可重名。`status` 显示七轴角度和当前片段。

先用 `stop` 正常保存片段，再输入 `quit` 或第一次按 Ctrl+C：程序结束采集，保持重力补偿并用约 0.5 秒逐渐接入位置控制增益，然后回到机械校零位；确认稳定到位后才请求失能、检查状态、关闭连接并导出 CSV。J1～J6 的目标为 0 rad，夹爪保持退出时的开度，不自动闭合；不会回到待机预设。未 `stop` 的片段仍标为不完整，回零运动不计入片段。

回零直接复用 VR 项目的 `runtime.safety.move_to_zero_pose` 和 `MITCommandDispatcher`，参数读取 `config/rs_mit_split.yaml` 的退出归零及 MIT 配置。当前配置为回零速度 0.5 rad/s、加速度 1 rad/s²、到位容差 2°、总超时 30 秒、停滞检查 5 秒；参考流程还检查连续稳定时间及近零速度。记录时的 ±3° 测量容差不会扩大轨迹目标限位；参考回零规划器自身的反馈边界检查仍保留。代码、配置和模型在使能前准备完成，回零过程中持续检查反馈、身份和看门狗。

**回零过程中再次收到 Ctrl+C 或 SIGTERM 会中断回零并失能到外部支撑。** 录制中首次 SIGTERM、输入结束 EOF、显式设置的会话时限到达，均走正常回零流程；反馈/驱动故障仍优先中止运动。初始化或使能未完成时的退出不会启动回零。回零发生异常或被中断时，摘要为 `zero_return_completed=false` 且会话失败，不声称已归零。普通退出成功回零时该字段为 `true`，然后才执行失能。日志可用时保存 `zero_return_policy`、请求/完成/失败事件和独立运动样本。

日志写入失败（包括磁盘满）、队列满或异步保存待机预设失败时：完成使能的实机会结束采集，在有效反馈下回零后失能。故障日志停止继续入队，只在内存保留首个错误；原始 CAN 解析、七轴反馈核验及回零命令发送不再依赖日志写入成功。回零中才出现日志故障也继续受控回零，反馈/驱动异常仍中止。结果保留 `logging_errors`，会话 `success=false`，导出的片段全部标记为不完整，不因成功回零就声称录制成功。若磁盘连摘要也无法保存，硬件清理仍先完成，终端返回结构化结果并报告摘要保存失败。此策略仅适用于录制器，且不能保证恢复未写入磁盘的样本。

独立看门狗忽略进程组收到的 SIGINT/SIGTERM，由主程序执行上述退出策略；主程序失联或退出导致管道断开时，看门狗仍请求失能。SIGKILL、断电和控制进程卡死不能执行软件回零。

以上退出回零适用于 `record_daily record`。`mock` 不模拟这段实机运动；`play_daily` 的退出行为见下方 CSV 播放说明。

录制中任一轴温度达到 **100°C**，在七轴位置、原始回包、状态新鲜度、模式和故障检查全部通过后，结束采集并执行同一套受控回零，再失能。摘要记录 `reason=temperature`、触发电机与温度，以及 `zero_return_completed`。尚未正常 stop 的片段保留数据但标为不完整，回零不录入片段。回零期间不再用同一个 100°C 软件阈值重复中断，但持续核验反馈和电机故障，保留参考回零的超时、停滞检测及 Ctrl+C 中断。不能据此保证已报告硬件过温故障的电机仍能运动：高温与任何真实反馈/驱动故障并存时，故障优先，失能到支撑。启动前已经达到阈值时拒绝使能，不为降温主动启动运动。此温度回零策略仅适用于录制器，CSV 播放的温度退出仍为失能。

实机会话默认不限时（`--seconds 0`），由 `quit` 或首次 Ctrl+C 回零退出。可显式指定正数，例如 `--seconds 1200` 表示就绪后 20 分钟结束采集并回零退出；启动时显示所选时限，元数据保存 `session_limit_s`（不限时为 null）。会话时限不再限制为 600 秒。未先 `stop` 的片段到时仍标为不完整，回零不录入片段；单个用于 CSV 播放的动作仍须符合播放器自身的 600 秒/30001 样本上限。持续防坠支撑必须在整个会话有效。正常退出未确认失能时返回失败并明确报告，不能把终端退出等同于机械臂已稳妥停住。

## 控制与反馈

- 参考用户提供的 `reBot-B601-RS-for-mujoco_sim/examples/09_real_to_sim_gravity_comp.py` 和 `control/gravity_compensation.py`：Pinocchio 计算 `g(q)`。
- 采用标定绑定的六轴模型（夹爪指固定在模型零开度），保留其质量、惯量与关节变换；与提供的八轴模型在指关节为零时对照重力力矩。非标准负载或明显不同的夹爪开度需要更新模型/验收。
- 六轴 MIT `kp=0`；力矩为 `ramp × g(q) − D × dq_est`。`dq_est` 来自实测位置差分和低通滤波；MIT `kd=0`，避免重复阻尼，也不依赖参考项目已记录异常的 mechVel 寄存器。
- 夹爪用低位置增益保持启动实测开度，不指令闭合或张开；偏离初始开度超过 2° 时退出。当前未标定的夹爪全行程不会被转换成虚构的百分比。
- 每轮只发起一次七轴 mechPos 参数请求批次；读取不会发零力矩 MIT。独立接收器用内核时间戳校验参数回包与状态帧、模式、故障和温度。SDK 位置必须与本轮新鲜原始参数回包一致；异步状态帧的位置不再用假定拖动速度上限作差异判断。
- 模型边界的位置测量容差按用户要求设为 3°，读取入口与重力补偿循环共用同一常量，并写入会话元数据。保留实测角度，不裁剪、不补零；最终目标及录制动作的模型限位不变。自动过渡允许从容差内的实测起点向原限位内恢复，位置保持与过渡共用该起点范围，不统一放宽所有目标。
- 50 Hz 为目标频率；记录真实单调时间戳和每批读取起止时间，七轴样本不是严格同时测量。批次/循环/样本间隔超过 100 ms 则退出。按用户要求，手动拖动不设置速度提醒或速度退出阈值，不裁剪实测速度；速度仅用于记录和阻尼计算。反馈有效性、位置范围及力矩预算检查继续生效。记录不被重采样伪装为稳定 50 Hz。
- 检查完整重力与总力矩预算，超限退出而非悄悄截断。当前预算为 J1–3 各 18 N·m、J4–6 各 4.5 N·m、J7 1.5 N·m（2026-11-02 按用户要求统一提高50%）；属于软件估算阈值，不代表电机连续额定值或实机已验收的性能。与CSV/daily播放及自动待机过渡共享；独立VR回零前馈限制及回零容差不变。
- 磁盘写入使用有界后台队列，队列满/写失败会触发退出。原始 CAN、控制量和被拒绝的已读位置尽量保留用于诊断。
- 复用现有独立进程看门狗，心跳丢失约 0.4 秒会请求失能；这依赖实际机械支撑，不能覆盖断电、CAN 断线或整机崩溃，不能替代独立停机措施。Python/Linux 控制循环不具备硬实时保证。

## 文件与后续处理

每个会话创建独立目录 `record/gravity/<UTC时间>-<唯一编号>/`，不会覆盖旧录制。可以用 `--output` 改变父目录。

| 文件 | 内容 |
| --- | --- |
| `metadata.json` | 标定内容及 SHA-256、模型 SHA-256、Python/驱动、控制参数、是否 mock |
| `session.jsonl` | 片段起止、实测位置、原始差分/滤波速度、重力与发送力矩、读取时间、退出事件 |
| `can.jsonl` | 带内核接收时间戳的原始 CAN 帧，以及校验前的 `sdk_position_batch`（含 SDK 值/读取区间/错误）；mock 时为空 |
| `idle.csv` 等 | 每段真实时间、七轴原始位置 rad、估算速度 rad/s、前馈力矩 N·m |
| `summary.json` | 会话结果、退出原因、失能确认、片段完整性、样本数、CSV 校验值 |

受待机约束的片段会在 `session.jsonl` 的开始事件和 `summary.json` 中保存完整预设快照及入口/出口规则，后续可以确认不同动作是否基于同一套待机角度。

`complete=true` 只表示片段通过 `stop` 正常结束且至少两点，不表示已通过实机回放验收。CSV 可交给下述播放器检查、生成平滑轨迹后试播，不直接逐行发送电机目标；不需要转换为 TCH。

录制中断时保留日志。断电/强制杀进程可能只留下部分 JSONL，不能把这种文件认作完整录制；仍可据已写入的行恢复数据。

## 直接播放 CSV

新增 `tools/play_daily`，接受本录制器生成的 CSV。保留 CSV 同目录的 `metadata.json` 和 `summary.json`，用于核对标定、模型、片段完整性及文件校验值。mock 数据、只有 `pose idle` 的 JSON 预设、未 `stop` 的片段、无匹配摘要的 CSV 都不能作为实机播放输入。

先关闭录制程序（`stop` 保存当前片段，再 `quit`），使用实际会话文件路径替换示例路径：

```bash
# 离线检查，不打开 CAN；显示起点/终点角度、重定时后的时长
./tools/play_daily inspect record/gravity/<会话目录>/idle.csv

# 支撑承重、确认到起点的运动空间无障碍，并关闭其他控制程序后试播一次
./tools/play_daily play record/gravity/<会话目录>/idle.csv --supported
```

播放前读取当前姿态并确认稳定，自动规划“当前位置 → 录制起点”的六轴同步过渡，不再要求手动摆到起点 1°以内。过渡复用现有 C2 五次曲线，验证关节位置极值、速度/加速度边界，并在不大于 20 ms 的规划时间间隔上检查重力力矩预算；规划后再次确认机械臂没有被移动，通过后才使能。先以 1.5 秒渐入建立当前位置保持与重力补偿，再按过渡轨迹移动到起点。到位检查要求误差≤1°且估算速度≤1°/秒持续0.5秒（最多等待5秒），未满足则停止，不开始播放。随后播放一次、末尾保持 1 秒并检查到位，再失能，由外部支撑承重。

**播放器首次 Ctrl+C 改为先回零再失能。** 完成使能后，无论正在建立保持、前往起点、播放或末尾保持，首次 Ctrl+C 都停止继续播放，复用录制器的 `rs_zero_return` / VR `move_to_zero_pose`，将 J1～J6 回到机械校零位并保持夹爪开度，确认稳定到位后才失能。回零所需配置和模型在使能前准备；交接时从最后成功发送的六轴 KP/KD 和重力补偿比例平滑接入回零控制，不先将位置保持增益降为零。摘要新增 `zero_return_requested`、`zero_return_completed` 和退出 `reason`。

回零中再次 Ctrl+C 或收到 SIGTERM 会中止回零并失能；反馈/驱动故障、使能未完成、连续两次 Ctrl+C 不启动回零。回零失败不会标记为已到位。此修改针对播放器 Ctrl+C；自然播放结束和 SIGTERM 仍按原策略失能，播放器尚未采用录制器的温度/存储故障回零策略。

自动过渡是关节空间的平滑运动，不包含障碍物检测、避障或碰撞验证，需要保证当前位置到起点的运动空间可用。当前位置仍须满足已有反馈和初始保持/曲线边界检查；过渡路径超限或重力预算不足会拒绝使能。终端显示过渡预计耗时，`--speed` 的额外减速同时应用于过渡和录制动作。

CSV 的实际时间和七轴位置用于轨迹构造；`ff*_nm` 列不会重放，而是按当前测量位置重新计算重力补偿。夹爪在过渡和播放全程保持**本次启动时实测开度**，不会为匹配旧片段自动开合。使用 C2 连续的五次样条，检查插值位置极值并重定时；位置超限不通过放宽测量容差或截断轨迹处理。默认 `--speed 0.5` 是在速度/加速度约束后的额外减速，可在 `(0, 1]` 内设置；基础播放速度上限为 0.12 rad/s，加速度上限为 0.25 rad/s²。录制拖动本身仍不按速度阈值中止。

播放复用录制器的新鲜 SDK/原始 CAN 对照校验、模式/温度/故障检查及失联看门狗，另检查跟踪误差和估算的重力加 PD 力矩预算。估算不是独立硬件力矩限制；轨迹检查不是碰撞验证。模型、机械安装和负载应与标定一致。代码已通过离线替身测试，未完成实机播放验收。

播放日志位于 `build/record-review/gravity-play-*/`，包含 `plan.json`、`entry-plan.json`（当前姿态、过渡目标、时长及峰值）、`control.jsonl`、`can.jsonl`、`summary.json`。退出后可查看 `entry_completed`、`success`、`disable_confirmed` 和具体异常。旧 TCH 播放器及其锁定状态不受这个 CSV 入口影响。
