# 舞蹈示教录制（旧菜单）

当前正式十组 Dance 见 [舞蹈资源](../gifs/dance/README.md)，使用 `tools/dance` 播放。本文的 `record_dance` 仍保留历史示教菜单和 ID 33–42，用于采集素材；这些编号已经从板端编舞库退役，不能直接作为新 ID 45–54 导入，也不代表当前 09“空间8字”。本轮 GIF 更新不修改示教控制行为。

使用 `tools/record_dance`，复用 `rs_gravity_record.py` 的重力补偿、采样、日志、回零和故障退出流程。本工具只采集动作，不自动播放或导入板端编舞。

十个基础动作中，只需录制 01～08 和 10 共九个动作；09 夹爪开合留待后续程序生成。独立的开场、收尾动作也无需录制。每段基础动作的首尾姿态检查仍保留，用于后续衔接。

## 启动

先安装能独立承重的防坠支撑。`--supported` 表示支撑已安装，不能仅以清空周围代替。

```bash
cd /home/verser/esp32/reBuddy/tools
./record_dance --check
./record_dance --supported
```

`--check` 只离线检查环境；`--list` 只显示动作菜单。均不连接 CAN。
默认使用 LeRobot 虚拟环境和 `can0`；可通过 `REBUDDY_PYTHON` 与 `--port` 修改。

默认从 `record/daily_ready/manifest.json` 读取 Daily 的统一待机姿态，连接机械臂前核对标定、模型和关节范围。启动后先回机械零位，再平滑到 Daily 待机姿态；稳定到位后切换为重力补偿并等待动作编号。首次使用也无需输入 `pose`。待机数据缺失或不匹配会拒绝启动，不自动退回手动模式。

等待时为重力补偿示教状态，可以拖动，不是刚性位置锁定；录制开始前仍会检查你是否在统一待机姿态。只有高级 `--manual-start` 模式才使用舞蹈目录的独立姿态预设，并允许手动 `pose` / `pose replace`。

## 录制

```text
01         开始录制点头打拍
stop       停止拖动，自动回到统一姿态，检查通过后结束片段
01         再录一份点头，自动使用新编号
stop
quit       回零后失能退出
```

以上为逐步输入示例，不要整段粘贴。开始前在统一待机姿态保持一秒，输入编号后拖动录制。动作完成后停止拖动并让出回位路径，输入 `stop`，程序平滑切入位置控制，直接回到该片段的待机预设，不绕行机械零位。回位的实测运动也录入当前片段。在位置保持阶段稳定至少 1.1 秒后，检查各轴相对预设误差不超过 ±2°、最近约一秒的数据连续且各轴波动不超过 0.5°；通过后才标记完整，再渐变回拖动补偿。切回补偿的漂移不录入已完成片段。回位或检查失败会走保护保持流程，片段保留为未完成。

| 编号 | 动作 | 文件名前缀 |
| --- | --- | --- |
| 01 | 点头打拍 | dance_nod |
| 02 | 抬臂舒展 | dance_lift |
| 03 | 深蹲回升 | dance_dip |
| 04 | 前探伸展 | dance_reach |
| 05 | 底盘回转 | dance_base_turn |
| 06 | 大幅摇摆 | dance_sway |
| 07 | 折肘展开 | dance_elbow |
| 08 | 抬头俯看 | dance_wrist |
| 09 | 夹爪开合（程序生成，无需录制） | — |
| 10 | 大幅波浪 | dance_wave |

也可以输入中文动作名或英文 key（如 `nod`）。`help`/`list` 重看菜单，`status` 看当前角度及相对姿态偏差。默认共用 Daily 姿态，不允许 `pose` 替换；高级手动模式下才可用 `pose replace` 更新独立预设。旧片段保留原始姿态和标定信息。

重力补偿录制期间夹爪保持固定开度，其余动作仍记录包括夹爪反馈在内的七通道。选择 09 会提示无需录制，不创建片段，也不改变夹爪控制。后续通过程序设置开合幅度、次数和拍点；当前录制入口不执行夹爪表演。

舞蹈 `stop` 会自动回到待机姿态后结束片段，随后恢复重力补偿，可继续录下一动作。等待“片段完整结束”后再输入下一编号或 `quit`；回位途中 `quit` / Ctrl+C 会中断片段并请求回零退出，不能将片段标记完整。需要制动并固定姿态时输入 `estop`（或 `pause`），自动回位期间同样有效：充分建立重力补偿后，会先阻尼制动，再锁定一次实测姿态并渐入位置保持。保持期间不继续录制、不自动恢复，也不会自动回零；输入 `home` 或 `quit` 请求回零退出，`release` 明确请求失能。制动尚未完成时会提示稍后重输回零命令。

正常录制时 `quit` 或首次 Ctrl+C 仍请求回零退出。运行异常、充分建立补偿后的日志故障，以及回零异常会尝试同一保护保持；保持中 Ctrl+C 不释放力矩。未完成使能/重力渐入、反馈不可信、驱动故障、保持力矩超限或保持控制失败时，不能保证定姿，会明确提示并尝试失能到支撑。严重温度告警沿用受控回零策略；进程被杀死或看门狗失联仍可能失能。软件保持依赖供电与 CAN，不能代替机械防坠。

## 数据

默认保存至 `/home/verser/esp32/reBuddy/record/dance/<唯一会话目录>/`，不覆盖 Daily：

- `dance_nod_01.csv` 等：目标 50 Hz 的实际七通道采样，保留实际时间戳。
- `metadata.json`：标定、模型、录制策略和十动作清单。
- `session.jsonl` / `can.jsonl`：完整日志及首尾检查证据。
- `summary.json`：完成状态、CSV 校验和、首尾姿态记录。

CSV 在会话结束、硬件清理后导出；录制中先写日志。`stop` 成功表示片段结束已记入日志。未正常结束的片段保留为不完整，不代表可播放轨迹。首尾验证通过也不等于运动路径或编舞已通过实机验收。

默认待机姿态来自 Daily 清单，其数值、来源哈希和标定身份会写入录制元数据。重新校零后须更新匹配的 Daily 数据。`--output` 只改变录制保存位置，不改变默认姿态来源。高级手动模式才使用输出目录中的 `presets/idle.json`。

建议第一份录点头：保持起始姿态 → 连续三次自然点头 → 停止拖动，输入 `stop` → 等待自动回位及“片段完整结束”。不必强行跟上 GIF 的 2.4 秒，后续再处理节拍与衔接。

## 保留节奏的缩幅试播

`tools/play_dance prepare 原始.csv` 生成独立的 `record/dance_prepared/<会话>/动作.json`，原始文件不变。先用误差不超过 0.5° 的稀疏曲线拟合手动段，再围绕统一待机姿态缩小幅度，以满足项目已有的 1 rad/s、2 rad/s² 试播预算并保留 5% 余量；不改变手动段时长。自动回位尾段重建为同样时长的平滑返回，去掉切回拖动补偿的漂移。夹爪保持当前开度。

可处理完整的自动回位片段，或唯一错误为“自动回位未通过首尾检查”、日志无丢失且手动段边界有效的片段。其他故障片段仍拒绝处理；不修改旧摘要的 `complete` 标记。加载处理版本会重新核对原始 CSV、元数据、摘要、标定和全部生成参数。

```bash
./tools/play_dance inspect record/dance_prepared/<会话>/dance_nod_01.json
./tools/play_dance play record/dance_prepared/<会话>/dance_nod_01.json --supported
```

先缓慢前往起点，再播放一次。完成后保持力矩，输入 `home` / `quit` 回零并确认到位后退出。`stop` / `estop` / Ctrl+C 请求制动保持；运行异常也尝试同一保护保持，依赖供电、有效反馈和 CAN。`release` 明确失能，需要支撑承重。

2026-11-07 点头样本 `20261107T082540Z-1794039940384351464` 的缩幅版本完成了一次实机试播：整段 19.32 秒，手动段 11.20 秒，幅度约 6.8%，J4 总摆幅约 3.69°；播放段最大跟踪偏差约 0.84°。完成后保持，收到 `home` 后确认回零及失能。原始录制及试播日志已清理，本文仅保留历史结果摘要。这是该缩幅版本的单次结果，不代表原幅度、原速度或所有动作已验收。
